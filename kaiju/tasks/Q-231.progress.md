## Audit findings
- Build: PlayerBuild.cs uses BuildTarget.StandaloneWindows64; scripting backend is the project default (Mono; ProjectSettings lists only Android override). IL2CPP would need VS C++ workload on the build host; not used, leave Mono. Output `<out>/b1/KaijuGame.exe` + `KaijuGame_Data/`; manifest finds boot.config under `*_Data`. Smoke skipped on Mac by design.
- Graphics API: no Standalone `m_BuildTargetGraphicsAPIs` entry, so Unity auto list (Unity 6000.6: D3D12 first, D3D11 fallback on Windows). No `#if UNITY_STANDALONE_OSX`, no `SHADER_API_METAL`/`only_renderers` anywhere in Assets (shaders/hlsl/compute grep empty). No GraphicsDeviceType branching in runtime code.
- Native/platform: only DllImport is `libSystem.dylib` in `Game.Perf.Bay/M008BayRun.cs`; that asmdef is Editor-only (includePlatforms Editor) and the call is try/catch, so it never ships in a Windows player. No hard-coded `/Users`, `/tmp` literals in runtime code.
- Paths: all runtime file access uses `Path.Combine` on `Application.streamingAssetsPath` / `dataPath` / `persistentDataPath`. Tile folders `L<n>/<ii>_<jj>`, journal `L<n>_<ii>_<jj>.journal`: no characters illegal on Windows, no case-only differences. Mixed `/` inside `Path.Combine` is accepted by .NET on Windows. Risk: MAX_PATH 260 (long build dir + `KaijuGame_Data/StreamingAssets/Geo/tiles/v1/L1/30_36/...`); build under a short path (e.g. `C:\kb`).
- Existing non-Windows-specific caveat: SliceBootstrap needs scene-carried config (player has no Assets/); same on macOS.
- Pixel pipeline: internal RTs are explicit `GraphicsFormat` (R8G8B8A8_UNorm/SRGB, R32_SFloat, R8G8_UNorm), all mandatory render-target formats on D3D11/12; HUD uses RGBAHalf texture (T-154b). PixelPresentFeature decodes sRGB only when the final target is null or an sRGB format: this relies on the backbuffer being an sRGB view in the linear project (Metal behaviour proven; D3D flip-model swapchain `useFlipModelSwapchain: 1` is expected to match but is NOT proven). The T-154 HUD brightening was a Metal backbuffer effect: unknown on D3D.
- Audio: AudioManager default backend (FMOD inside Unity), no platform branching in Game.Audio; `SliceAudioBehaviour` uses plain AudioSource. Nothing Windows-specific found; untested (no audio per brief).
- Resolution/window: smoke uses `-screen-width/-height -screen-fullscreen 0 -popupwindow`; all supported Windows player args. fullscreenMode 1 (fullscreen window).

## Cannot be verified without Windows (checklist, run on a Windows 10/11 x64 machine, GPU with D3D11 FL11)

1. Unzip/copy the build to a SHORT path: `C:\kb\b1\` (keeps paths < 260).
2. Smoke (default API): `python -I Tools\Build\smoke.py --app C:\kb\b1 --out-dir C:\kb\smoke_default` -> expect `SMOKE PASS`, tiles 15, buildings_registered > 0.
3. Pass = exit code 0 (`echo %ERRORLEVEL%`), `[SliceSmoke]` line in log, no shader/pipeline errors (`findstr /i "error exception shader" C:\kb\s11.log`). Record which API was chosen by default (first line `Direct3D 1x` in log).

8. Audio: launch, confirm sound device init in log (`FMOD` lines without `ERR`) and audible mix; not run here.
