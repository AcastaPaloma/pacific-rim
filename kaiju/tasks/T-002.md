# T-002 · Headless metric tools for M-001 to M-004

Milestone: **M0 · Foundations** (the gate is measured with these tools). Orchestrator §4.2: "Implementation agents build the capture and measurement tools in `Tools/Metrics/`. Metrics must run headless and repeatably."
Owning module: **Tools/Metrics** (Python, kaiju conda env; no Unity dependency). Worktree `.wt/T-002`, branch `task/T-002`.
Evaluation panel: `eval-arch`, `eval-style` (validity of the style metrics on the references and controls), `eval-feel` (validity of the gait metrics on synthetic logs).

## IDs this task carries (full text)
- M-001: "Feels heavy | Gait Froude number within the target band. Peak acceleration and turn rate below derived limits. Time-to-stop matches mass. Panel score ≥ 8/10 on "feels like 10,000 t""
- M-002: "No foot sliding | Planted-foot slip per contact < 0.5% of foot length"
- M-003: "Matches the style references | Share of pixels within palette ΔE tolerance ≥ 95%. Dithering present in gradients. Value banding by depth is monotonic. Blind evaluator panel style-match ≥ 8/10"
- M-004: "Pixel stability | Measured shimmer and crawl during camera translation and rotation below threshold"
- Orchestrator §4.4: "**Version metrics.** Evaluators use only registered, versioned metrics plus their rubric. A new metric goes through steps 1–3 before it can fail anything."
- Orchestrator §1.6: "**Evidence over claims.** Nothing is "done" without evaluation evidence (artifacts, metric values, test results) linked in the ledger."

Pillars: P1 (M-001, M-002), P4 (M-003, M-004): these tools are how every later slice proves it serves them.

## Linked research and contracts (binding)
- `research/R-001.md`: `M-001@v1`, `M-002@v1` and the `gait_log@v1` input schema.
- `research/R-002.md`: `M-003@v1`, `M-004@v1`, `palette_set@v1` (`research/R-002/palettes.json`) and the `style_capture@v1` input contract. Research scripts in `research/R-002/scripts/` are notes, not the product: reimplement cleanly.

## Scope
1. A Python package under `Tools/Metrics/` with one command-line entry per metric (`python -m …` or a single CLI with subcommands): input = the contract files (`gait_log@v1`, `style_capture@v1`), output = a JSON report (metric ID and **version**, every sub-measure with value, threshold, pass/fail, the input file hashes, tool version) plus a short human-readable summary and optional diagnostic images (for example a ΔE heat map, a slip plot). Exit code reflects pass/fail.
2. Implements **every** sub-measure of `M-001@v1`, `M-002@v1`, `M-003@v1`, `M-004@v1` exactly as specified. Thresholds are read from a versioned registry file (`Tools/Metrics/registry/*.yaml` or JSON), never hard-coded, so founder calibration (orchestrator §4.3) is a data change that bumps the version.
3. Schema validators for `gait_log@v1`, `style_capture@v1` and `palette_set@v1` with clear errors, so implementers can check their emitters early.
4. **Self-validation fixtures** (generated by script, deterministic, small): synthetic gait logs with known Froude number, known slip, known acceleration; synthetic images with known palette adherence, with and without ordered dithering, with monotonic and non-monotonic depth banding; synthetic frame sequences with known shimmer. `pytest` proves each sub-measure returns the known answer and fails the negative control.
5. A run on the reference panels (style metrics that apply to stills) with results stored as a baseline.
6. A `README.md` (how to run each metric, inputs, outputs, how to add a metric version) and a `MODULE.md`.

## Constraints
- kaiju conda env only; no new dependency unless added to `environment.yml`. Headless (no display), deterministic (fixed seeds), each metric under 60 s on a typical input.
- A metric must never pass by default: missing or malformed input is an error, not a pass.
- Do not tune thresholds to make anything pass. Disagreement with a research spec is reported as a defect against the spec (proposed `Q-###`), not silently changed.

## Evidence required in `evidence/T-002/`
`pytest` output; the JSON reports for all fixtures (positive and negative); the reference-panel baseline reports; `EVIDENCE.md`.
