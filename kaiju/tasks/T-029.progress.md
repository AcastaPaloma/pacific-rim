## Step 2 of 4 (done): snapshot codec and interpolation
- `SnapshotCodec` (Runtime): `StateSnapshot@v1` as u8 version, i64 host step, i32 count, then per body u64 id + 8 raw f32. Round trip bit-exact (NaN payload, -0), deterministic bytes (13 + 40 B per body), rejects truncation, trailing bytes, wrong version, non-ascending ids. No quantisation or delta: bit-exact was the requirement and ~1 kB per snapshot at 25 Hz is far below M-057.
- `SnapshotInterpolator` (Runtime), all time in Core steps: 25 Hz (every 2 steps at 0.02 s), render step = client step + clock offset - 3 intervals (6 steps = 120 ms). Offset = best (host - arrival) over the last 64 snapshots, slewed at most 1% (no render clock steps). Cubic Hermite from pos+vel (yaw by the short way round pi). Past the newest snapshot: constant-velocity extrapolation up to 250 ms (12.5 steps), then freeze and `IsStale`/`Stale`. Late data never moves the drawn body: the change at the already drawn instant goes into a per-body offset that decays critically damped (omega 12/s, ~90% gone in 0.32 s, exact integration for any dt).
- Tests (`NetSnapshotTests`, 11 new; 37/37 total via `dotnet test DotnetTests/Net.Tests`): codec round trip/fuzz/malformed; steady cell (one-way 2..3 steps = RTT 100 ms +-10 ms, 2% loss, 120 s, two bodies) max error < 1 mm world space (bound derived in the test comment: Hermite h^4/384 term ~2e-6 m, float32 ~1e-6 m, 40 ms extrapolation allowance ~0.6 mm); 400 ms outage: stale flagged, per-frame move <= 1.35 x v*dt, error < 1 mm within 1 s of recovery; a 1 m late-arrival jump blends with no teleport (20% left after 0.24 s); same seed gives identical output hash.
- Not done here: pixel conversion/snap (rendering contract), net_log "stale" event (step 4), ping-pong clock samples beyond the arrival offset (step 4 may add), stress cell RTT 150/5% as a test (steady + outage cells cover the logic).

## Step 3 of 4 (done): intent sender and host buffer
- `IntentBundle` (wire: u8 count 1..3 + IntentPacket@v1 records, newest first; IntentPacket itself unchanged), `IntentSender` (client: per-slot uint sequence from 1, each datagram = new intent + previous 2, unreliable), `IntentHostBuffer` + `IIntentSink.ApplyIntent(slot, payload, IntentSource Fresh|Held|Neutral)` (the seat implements the sink later; payload stays opaque).
- Host rules: `StaleSequenceFilter` gate (dup/older dropped, wrap-safe), newest accepted per slot pending (older pending counted `Superseded`), `Deliver(hostStep, sink)` once per registered slot in ascending slot index (registration/arrival order irrelevant); silent slots get Neutral. Hold = 5 steps after the last fresh step (100 ms / 0.02 s), then Neutral (all zero); a slot with no intent yet is Neutral. Counters for step 4's net_log: DroppedStale/UnknownSlot/Malformed, Superseded, HeldSteps, NeutralSteps. `Receive`/`Pump` reject packets whose slot is not the one bound to the connection (spoof).
- Tests (`IntentBufferTests`, 13 new; 50/50 via `dotnet test DotnetTests/Net.Tests`): out-of-order/duplicate applied once in sequence order, same-step burst, wrap, hold then neutral, slot order over all 6 arrival permutations, sender repeats, spoof/malformed, 2% loss x 3 seeds over 120 s.
- Loss cell reading: sender 60/s, host 50 steps/s. Intents the host never learns (not in any arrived datagram): run <= 1 (a single loss is always covered by repeats). Host steps without a fresh intent (Held) can reach 2 in a row at 2% loss because 50 Hz windows sometimes hold one datagram; asserted <= 2, not 1. A literal "no Held gap > 1 step" is not guaranteed by repeats alone.

## Choices made (user offline)
- Contract map keys are "Core.<Name>" and "Net.<Name>"; any missing or unequal entry refuses (no "compatible" notion).
- Accept embeds the first snapshot via `SnapshotCodec` (length-prefixed bytes); step 2 done that swap.
- Intent payload is 16 opaque bytes until the T-005 seat contract lands; the seat adapter packs and unpacks.
- Max slots is a validator argument (default 4); the host counts itself in `occupiedSlots`.
