## Decisions (Assumed, recorded)
- **Handler shape:** `IEventHandler<T>.Handle(in T)` interface objects instead of delegates: no closure allocations, stable subscriber identity for error reports, and `Unsubscribe(this)` is trivial.
- **Typed events:** `where T : unmanaged, IEvent` makes "no managed references in events" a compile error; the reflection scan is a backstop.
- **Re-entrancy rule:** "a handler receives exactly the events published after it subscribed and before it unsubscribed", implemented with a publish sequence number per subscription and per queued event. This is one rule that covers all four re-entrancy cases.
- **Cascade cap:** on overflow the remaining queue is dropped and the outermost `Publish` throws. The in-flight event still finishes its handler list.
- **Thread check is always on** (one int compare), not only in development builds: cheaper to reason about.
- **Floats in saves** are stored as IEEE-754 bit patterns (`{"f64":"400921FB54442D18"}`): bit-exact and locale-proof on both Mono and CoreCLR without relying on either runtime's round-trip formatting. Values this build does not understand are kept verbatim (`Raw`).
- **Envelope vs section versions:** the envelope schema (Core) is 1; each module's section carries its own version and migrations. The sample v1→v2 migration is a test-only section (`sample.inventory`).
- **Feature flags as a folder** (orchestrator note 2, mid-task): `Assets/Game/Config/FeatureFlags/<Module>.json`, merged in ordinal file-name order; a duplicate name or a malformed file turns everything off with one error. In the editor the Resources pointer re-reads the folder at each boot and before each build, so adding a module's file needs no manual step.
- **Integration metas** (orchestrator note 1): merged `origin/claude/fable-orchestrator-prompt-83a0a8` (commit `f561cc6`) before Unity first generated any meta, so `Assets/Game.meta`, `Assets/Game/Core.meta`, `Assets/Game/Config.meta` are the integration branch's; no conflicts.
- **Fixed step:** kept 0.02 s as the brief instructs, marked Assumed in `CoreSettings.json`. `research/R-005.md` (landed during this task) R2 recommends **1/60 s**. Changing it is the one value in `CoreSettings.json`; nothing in code or tests depends on 0.02 except the sample constants inside tests.
- **Dotnet target:** tests run on net11.0 (the installed SDK/runtime); Core and Contracts compile as netstandard2.1 with LangVersion 9.0 to match Unity 6000.6's API surface and C# version (Unity's generated csproj: `netstandard2.1`, `LangVersion 9.0`).

## Findings worth knowing
- **Unity's Mono returns 0 from `GC.GetAllocatedBytesForCurrentThread()`.** The positive-control test proves it (1000 × `new byte[64]` → 0 bytes, 1000 GC.Alloc samples). The Unity runner therefore measures with a `ProfilerRecorder("GC.Alloc")` (same setup as the Test Framework's `Is.Not.AllocatingGCMemory()`); dotnet measures bytes.
- **`Type.Name` allocates a new string on every call in Mono** (cached in CoreCLR). The first Unity run showed exactly one allocation per outermost publish from `_cascadeRoot = typeof(T).Name`; fixed by storing the `Type` and building the name only on the error path. Worth a line in the coding guidelines for every module.
- Batch-mode `EnterPlayMode`/`ExitPlayMode` yield instructions work in an EditMode `[UnityTest]`, so the domain-reload-disabled re-entry check runs inside the normal EditMode suite.
