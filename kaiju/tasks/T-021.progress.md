## Step 3 written (Unity not yet run)
- `Runtime/GeoEdgePolicy.cs` (engine-free): for each border shared with a tile of the set, both tiles take the mean of the two tiles' r16 data heights (corners: mean of every set tile containing the point, summed in (j, i) order, so all tiles get the identical float). Applied to the tile's data lattice before meshing, so render mesh, `SampleData` and collider all see the shared heights. No neighbour: policy is null, output unchanged.
- `RtinMesher.Build(..., forceEdges)`: forced border nodes get infinite error, so every node of a shared border stays a vertex; null/all-false is byte-identical (test).
- Unity: `GeoBuildOptions.Edge` -> `GeoTileContext.Edge`; `GeoTileSetBuilder` computes the policy from the set (membership, not build order; edge profiles cached). Collider: heights now quantised on an absolute 0.005 m lattice (`GeoTileInstance.ColliderStepM`, base = multiple of the step, range 65535 * step = 327.7 m) so equal edge heights store equal values in both tiles. A tile range above 327 m (none of the 15 real tiles; max is 325.9 m before the mean) falls back to a doubled step with seams up to step/2.
- Tile roots are at multiples of 2048 m and terrain size is exactly 2048 m, so collider bounds touch with zero overlap.
- Tests: dotnet 57 (5 new in `Tests/EditMode/GeoEdgePolicyTests.cs`). Unity EditMode (GeoMultiTile, fixture now builds terrain colliders): `SharedEdge_RenderVertices_IdenticalInBothMeshes`, `SharedEdge_NoCrack_BetweenVertices`, `SharedEdge_Colliders_MeetWithoutGap`, `ColliderBounds_Touch_WithoutOverlapBeyond005m2`.
