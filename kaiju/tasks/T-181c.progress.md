## Brief
Goal: with `rendering.pixel.layerSnap` on, the rig fills `PixelStabilisationHints` v2 (`LayerCount` 3, `LayerNear/Main/Far`) by running `CameraStabiliser.Stabilise` once per layer, each with its own `SnapState` and reference depth. Flag off (default) = v1 path untouched, `LayerCount` 0.

Design (from MODULE.md "Layer slabs", T-181 note):
- Reference depths: near = the rig's focus depth (`m_ReferenceDepth`, 124.2 m in T1), main = skyline design depth (settings `skylineDepthM`, 664.874 m), far = far design depth (settings `farDepthM`, 10353 m). Scripted captures can override main/far (`SetScriptedLayerReferences`, e.g. 663.0 for the c11 reference-class edge).
- Main layer is the rendered pose: the v1 fields of the hints are the main stabilise result bit for bit (so `ReferenceDepth`/`PositionGrid` are the main's when layered); `LayerMain` = offset 0, own SubTexel, depth, grid.
- Near/far: same wanted pose, same (pure-function) rotation quantisation, own incremental snap state. Offset = layer snapped position minus main snapped position projected on the rendered right/up axes (m); remainder and grid are the layer's own.
- Per-layer `Cut`: the layer restarts from the wanted position when the global cut fires, when its state is not yet valid, or when its reference depth changed by more than the relative `GridTolerance` (1e-4, same value as `PixelLayerPlan.GridTolerance`; Camera cannot reference Pixel.Maths). Only that layer's `Cut` is set; the v1 `Cut` stays main's.
- Unusable layering (snap off, depths not strictly increasing and positive, no grid) returns false: the rig publishes the plain v1 hints (`LayerCount` 0) at its own reference depth and clears the layer states so the next layered frame restarts every lattice.
- Zero allocation: `Stabilise` allocates basis arrays today (existing, unchanged); the layered wrapper adds none of its own beyond those three calls. Test measures the wrapper against three plain calls.

Engine-free: `Camera.Maths/CameraLayerStabiliser.cs`, tests in `CameraMathsTests.cs` (dotnet Camera.Tests + Unity EditMode). Unity side: `ThirdPersonRig` wiring + settings keys, EditMode rig test.
