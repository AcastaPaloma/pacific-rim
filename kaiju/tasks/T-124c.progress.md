## What the profile says (the hitch attribution is the main result)
- The >33 ms frames are not one cause and mostly not in the code the flags touch: `StreamingScheduler.Tick` alone spikes to 35-42 ms (seeds 3-5 around 60-90 s and at 542 s; also in the rendered run with all flags off) = the "60 ms host.Tick stall" is the scheduler plan (stage 0), not Pump, GC bookkeeping or origin shifts (stages 1-4 stay < 5.3 ms). Render Pump item max 15-42 ms (L3/L0 render Build); brain phase 3 (kaiju motion + fire) 38-56 ms and Simulate 46 ms and destruction 41-56 ms show up as isolated stalls in unchanged code, i.e. machine noise (other jobs) lands in whichever phase runs; the A* searches are 7-11 ms max, 9 over 5 ms in 600 s (not the 56 ms spike).
- opt_v2 vs base_v2: seed 1 clearly better (max 32.5 -> 26.2 ms, frames > 12 ms 18 -> 7), seeds 2-5 worse or equal and the totals worse (11 vs 6 frames > 33.3 ms). Because the three flags ran together on a loaded machine the run cannot separate benefit from noise; nothing is proven, so NO default is flipped.
