# T-005 · One mech body that walks with physics and intent control

Milestone: **M0 · Foundations** ("One mech body that walks with physics and intent control." Gate: "Walk passes M-001 and M-002.")
Owning modules: **Physics.Body** (L1), **Control** (L3), **Units.Mech** (L3); consumes **Core** contracts (T-001). Worktree `.wt/T-005`, branch `task/T-005`.
Evaluation panel: `eval-feel`, `eval-physics`, `eval-arch`.

- M-002: "No foot sliding | Planted-foot slip per contact < 0.5% of foot length"

## Scope
1. `Physics.Body.Contracts` + `Physics.Body`: articulated body built at runtime or by Editor script from a **config asset** (segments, masses, inertias, joint limits, drive gains from R-005; nothing hard-coded), PD joint drives, mass properties, CoM and balance state, foot contact detection, `FootContact` event.
2. `Control.Contracts` + `Control`: `IPilotSource`, `PilotInput`, `IntentFrame`, `IIntentArbiter`, `PilotSeat`, `SinglePilotArbiter`; a scripted pilot source for tests and a device pilot source (Input System) for play.
3. `Units.Mech.Contracts` + `Units.Mech`: the mech assembly that wires frame + body + seat + locomotion controller (walk, turn, start, stop) implementing the approach recommended in R-005, within the limits in R-001.
4. A headless **walk scenario** runnable from the Unity CLI (PlayMode test or `-executeMethod`): flat rigid ground; scripted intent: stand 5 s, walk straight to steady state, turn 90°, walk, stop; emits `gait_log@v1` and `physics_log@v1`, plus a frame strip (side and three-quarter views) for the feel panel.
5. Physics check scenarios for `M-006@v1` (passive drop, static ground pressure, toppling fall).
6. Feature flags (default off), config assets under `Assets/Game/Config/`, EditMode tests for pure logic (engine-free where possible), PlayMode tests for behaviour, `MODULE.md` for each module.

## Constraints
- `MODULARITY.md` §5 recipe in order. Layers: Physics.Body may not reference Control or Units; cross-module calls only through `*.Contracts` and the Core bus.
- Real units and physics-derived masses. No kinematic cheating: the root is not animated or teleported, feet are not pinned by script, no artificial stabilising forces unless they model something real (thruster bursts are a later feature) and R-005 allows it. If full dynamic balance cannot be reached within the cycle, say exactly what assistance is used and how large it is (N, N·m), behind a flag, so the evaluators can judge it: never hide it.
- Deterministic scripted runs (same log on repeat within tolerance).
- Never edit `.unity`/`.prefab` as text; scenes for scenarios are built by Editor scripts or at runtime.

## Evidence required in `evidence/T-005/`
`gait_log@v1` and `physics_log@v1` files from the walk scenario; metric outputs for every sub-measure of `M-001@v1`, `M-002@v1`, `M-006@v1` with stored values; frame strips (PNG contact sheets, ≥ 2 full gait cycles, side and three-quarter views, with a scale marker); test result XML; `EVIDENCE.md` (artifact, command, commit).
