# T-004 implementation notes (impl-pixel)

Narrative, decisions and open points. Evaluators read `evidence/T-004/EVIDENCE.md`, not this file.

## What was built
- `Rendering.Pixel` (L1): contracts, engine-free maths, seven stages as separate URP 17.6 Render Graph renderer features, `PixelCameraBinder`, `PaletteProfile` assets with baked LUTs generated from `palette_set@v1`, an installer that creates the dedicated URP asset and its two renderers by Editor script. `MODULE.md` in the module folder.
- `Camera` (L3): `ICameraRig`, `ThirdPersonRig`, texel snapping, rotation quantisation, sub-pixel remainder, camera cut, footfall impulse by event contract. `MODULE.md` in the module folder.
- `Assets/Game/Tools/StyleCapture` (Editor-only tools assembly): the neutral style test scene and the haze calibration scene (built by script), the `style_capture@v1` capture tool and its jobs, the frame-timing tool.
- `Tools/Rendering/Pixel/*.py`, `run_evidence.sh`: checks the T-002 tools do not cover, evidence sheets, and the script that runs everything.

## Decisions (each Assumed unless a spec line is cited)
1. **Where Editor tools live.** MODULARITY lists `Tools/` at the project root, but Unity only compiles code under `Assets/` or a package. The capture tool and scene builder need both modules, so they are an Editor-only assembly `Game.Tools.StyleCapture` under `Assets/Game/Tools/StyleCapture/`; Python lives under `Tools/Rendering/Pixel/`. Alternative: a local package referenced from `Packages/manifest.json` (rejected: edits a shared file).
2. **Flags and the M0 configuration.** Core flag files must all be `false` (Core test `Flags_RepoFile_NewFeaturesDefaultOff`) and the session snapshot is fixed. A configuration file (`Config/Rendering/Configurations/M0StyleFrame.json`) lists the flags it switches on; `PixelFlagState.From(flags, configuration)` merges them. Stages are enabled by config, not code. Features check the binder's flag state per camera; the renderer asset is never mutated to toggle a stage.
3. **Stage order = feature list order.** All world stages inject at the same event, so reordering the list really reorders the stages (R-003 used distinct event offsets, which would make the list order meaningless). Post-processing is off on the pixel cameras (no tonemap, bloom, TAA or MSAA).
4. **Dither as a threshold texture.** The Dither stage writes a per-texel threshold; Haze (seams) and Quantise read it through the frame context. With Dither off they use 0.5: nearest colour and hard seams. No shader globals anywhere, so a disabled stage cannot leave stale state.
5. **Quantisation.** One 32³ LUT per profile (R-003): each cell holds two palette indices and a mix ratio found in OKLab with linear-light mixing and a penalty on distant pairs (Yliluoma). The LUT also carries the profile's grade: scene value (L*) is mapped along the profile's haze ramp (`ramp_uniform_L`), and saturated scene colours are pulled to the profile's accent. This is R-003's "ramp-constrained" strategy; it makes a neutral scene take the district's hues and makes value by depth follow the ramp. Index a is always the darker colour so the pattern never inverts between cells. `ditherSpread` (0.4) narrows the dithered zone between two colours so flat planes stay mostly flat.
6. **Haze works in scene space** (colour pulled toward an airlight value, then the LUT grades it onto the ramp), in bands with dithered seams. **Band spacing is even in log distance** between `hazeStartM` (60 m) and `hazeFullM` (20 km), not at equal transmittance steps as R-003 §5 derived. Reason, measured on the first captures: with equal-transmittance bands at a 20 km visual range everything within about 700 m is band 0, so an 80 m block 150 m away does not separate from its background (C7) and the near depth bands of M-003 c1 have no ordering. The reconciled spec tests outcomes, not the band formula. Alternative kept in mind: a second profile parameter for a transmittance exponent.
7. **Low-res target by a dedicated camera target** (R-003 option B) with a one-texel guard band and a padded projection; `color_internal` is the centre crop. The Store stage writes persistent internal colour (sRGB bytes, palette index in alpha) and linear depth, so the present camera and the capture tool read exact values and URP's own final blit is irrelevant.
8. **Field of view 60° horizontal** (R-002 §5 capture protocol; R-003 assumed 50° vertical). At 60° the whole-texel yaw step shifts the image by 1 to 1.33 texels across the frame, which rounds to one texel everywhere, so the direction-anchored pattern follows the image over the whole frame.
9. **Anchoring modes** as data (`ditherAnchor`): `screen`; `direction` (origin follows whole-texel rotation steps, which is what R-002's synthetic "direction-locked" case did); `hybrid` (dominant-axis triplanar world pattern with a power-of-two cell per axis within `hybridFarStartM` = 1500 m, direction beyond and in the sky). `hybrid` is the configured default because the reconciled spec names it as the default.
10. **Position snap is incremental.** The first version rounded the position to a lattice fixed in the camera frame (a pure function). Measured: yaw S_px 0.12 with direction anchoring, because the lattice turns with the camera and the position jumps on every rotation step. Now the rendered position steps by whole texels from the previous snapped position, so turning never moves the camera (yaw S_px 0.0008 with direction anchoring in the A/B set). Cost: the snap has one piece of state; a cut resets it. After an impulse the path back is not bit-identical (millimetres), then static again.
11. **M-004 sets are captured with `rendering.pixel.subPixelPresent` off.** The T-002 validator requires one `resolution` block per sequence, and with compensation on `output_block_offset_px` and `subpixel_offset_internal_px` change every frame. The internal image, index and depth do not depend on that flag (only the present stage reads it); the compensated output is captured in `c11_subpixel_on`. See proposed entries below.
12. **Smoothness (C11) is measured on the snapped plane**: the reference depth of the `c11_*` sequences is the depth of the tracked tower edge. Off that plane the edge is quantised to texels at a drifting phase (parallax), which no present shift can undo (R-003 §7).
13. **Camera impulse event** `CameraShakeImpulse { EntityId Source; float OriginX, OriginY, OriginZ; float ImpulseNs; }` is defined in `Game.Camera.Contracts`. At integration, adapt the mech task's foot-contact event to it (one event per footfall: contact point in world metres, contact impulse in N·s).
14. **Namespace `Game.Cameras`** for the Camera module, because a namespace `Game.Camera` hides `UnityEngine.Camera` inside every `Game.*` namespace that references it.
15. **Test scene tones.** Ground and forms have close albedo values and soft lighting so that mean value per depth band is ordered by haze and not by which object happens to be in a band; a pale gradient-lit cylinder and one saturated beacon (accent) are sized so they do not outweigh their band. The 1.8 m markers are 1.6 m wide so one always covers a texel centre at 600 m (point sampling would otherwise miss a 0.6 m figure about half the time; the Supersample stage is the general answer).

## Things that cost time (for whoever touches this next)
- `QualitySettings.renderPipeline` must be restored by asset path: opening a scene unloads unused assets and a plain reference to the previous pipeline asset becomes null, which then gets written into `ProjectSettings/QualitySettings.asset`. `PixelPipelineScope` handles it.
- A URP camera output texture needs a depth buffer, or Render Graph logs "Fake or uninitialized surface" and still renders.
- A `ScriptableObject` or `MonoBehaviour` class must be in a file of its own name or its asset loses its script on reload.
- An in-memory URP asset set as the quality pipeline did not become the active pipeline in batch mode; assets on disk do.
- `unity run` and `unity test` render with the GPU in batch mode on this Mac (Metal); `SubmitRenderRequest` works for both cameras.
- Re-running the installer or the scene builder rewrites the assets with new local file IDs (content unchanged). Do not re-run them without a reason.

## Not built, or built differently
- No CockpitRig (later module). The "rig gives no hints" path is tested without any rig.
- No PlayMode test: the capture tests and rig tests run in EditMode through explicit render requests and an explicit `Tick`, which is deterministic; a Play Mode run would add nothing the capture path does not already exercise. `ThirdPersonRig.Bind(registry)` (the Play Mode wiring) is unit-tested against Core's registry and bus.
- No quantisation hysteresis stage (R-003 stage 6, flagged "experiment, off").
- Light shafts, clustered smoke, dust: later slices (reconciled spec, last question).
- Per-pass GPU markers: the GPU recorder does not advance in a batch run without a player loop, so pass cost is measured as paired wall-time differences with a GPU sync per frame (see `StyleTiming`).
- The blind panel (M-003f) is a milestone gate; the board is prepared in `evidence/T-004/sheets/panel_board.png`.

## Proposed breakdown entries (placeholders; the scribe assigns numbers)
- **Q-NEW-a** · `style_capture@v1` and the T-002 validator disagree on per-frame output offsets. R-002 §6 defines `resolution.output_block_offset_px` and `subpixel_offset_internal_px` per frame (its example sidecar has non-zero values) and M-011 needs them per frame; the T-002 validator rejects a sequence whose frames do not share one `resolution` block. Recommended default: `style_capture@v1.1` states that those two fields may vary per frame and the validator compares only `internal_wh`, `output_wh` and `integer_scale`. Until then M-004 sets are captured with sub-pixel compensation off (decision 11).
- **Q-NEW-b** · Which anchoring mode is the M0 default? Measured on Unity captures (slate_teal, eye-height viewpoint; full table in EVIDENCE.md): `direction` meets every yaw threshold and the translation shimmer and flicker thresholds but misses translation crawl; `hybrid` meets every translation threshold and misses the three yaw thresholds. No mode meets both sets. Recommended default: keep `hybrid` as the reconciled spec says until the founders have seen both in motion, and recalibrate the yaw thresholds for surface-anchored dither (R-002 said its thresholds need recalibration on the first Unity captures).
- **Q-NEW-c** · Haze band spacing: log distance (built) or equal transmittance (R-003 §5)? Recommended default: log distance, with `hazeStartM` 60 m and `hazeFullM` 20 km per profile, judged by the style panel.
- **M-NEW-a** · Capture log cleanliness: a capture run must log zero errors and zero warnings (`capture_log_summary.txt`). Proposed as a sub-check of C19, because Render Graph errors do not stop a batch run.
