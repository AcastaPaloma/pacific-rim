# T-115e: C2 control (nofocus@1) translation check and M-007@v2 re-run on m007_bay_real@v1

## Cause
- The harness kept every position as float32 BayTM metres (10^4..10^5 m). That is a real defect (ulp 0.008 m at 10^5 m): translating a whole scenario changed the logs bit for bit (regression test fails on the old code). Fixed by simulating in a local frame (integer-metre origin = scenario spawn, planner via LocalFrameField, cost-field lookups and log writer add the origin back in double). Whole-layout translation is now invariant: 30 hunt runs (nofocus + candidate, 3 seeds, 3 shifts up to 100 km) and raid/mixed/emerge logs are identical apart from x/y.
- It was NOT the cause of the 0.70..1.00 swing of T-115d. Re-running that diagnostic with the fixed harness (`m007_bay_c2_translation_sweep.json`, flat map, LLMH+LMHH x 20 seeds, --hunt-shift) gives the same values as before the fix (0.870, 1.000, 0.696, 0.968, 0.995 vs 0.868, 1.000, 0.696, 0.968, 0.995). `--hunt-shift` moves only the spawn, not a translation of the scenario: the nofocus control has no pack layer, so when it sees no mech it walks to the nearest infrastructure node (SoloDecide), and the spawn-to-infrastructure geometry decides where it goes and when it meets the mechs. The control's ff is geometry-dependent (deterministic), the candidate is not (0.99994 at every shift). float32 precision moved the control mean ff by about 0.002 (default spawn 0.868 old vs 0.870 new), well inside sampling noise.

## Route for the lead (research item, no clause touched)
The ff metric saturates for this scenario (any brain that targets the nearest mech from shared positions focuses fire), so C2 cannot discriminate a control that is already ~0.97. Options: a control that actually spreads fire (target by member-nearest instead of the shared pack focus), or a geometry-fixed C2 scenario with mechs spread so unfocused fire is distinguishable. Needs a decision on the control definition, which is a clause-level change and so not done here.
