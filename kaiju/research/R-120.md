## 1. Question
What does Steam require us to disclose and prepare (AI-generated content, demo, store assets, build upload) for the M3 demo, what can be prepared without an account, and what must wait for a founder?

## 2. Headline
1. **Classification:** pre-generated AI = **yes** (Midjourney concept art, D-023; nothing of it ships as-is, but we disclose it); live-generated AI content = **no** (RL kaiju policies produce behaviour, not content; stated plainly in the free-text description, with guardrails written anyway).
2. Valve's AI section concerns "content that ships" and what players consume; efficiency tooling is "not the focus" [1][2]. Our reading is conservative: disclose D-023 art because it is a reference for shipped sprites/models.
3. Demo = separate app (type Demo) linked to the base app; Next Fest needs public base store page, public demo by start, game unreleased [4][6].
4. Required store art: header 920x430, small 462x174, main 1232x706, vertical 748x896, ≥5 screenshots at ≥1920x1080 16:9; trailer up to 1080p H.264, 60 fps allowed [3][5].
5. Everything to upload needs a partner account, the app ID and the SDK/steamcmd; VDF files and the folder layout can be prepared now [7].
6. SDK download needs a Steam account tied to a partner or acceptance of Valve's SDK Access Agreement: a founder action [8][9].

## 3. AI-generated content disclosure (Steam Content Survey)
### 3.1 What Valve says [1]
- Section scope: AI "in your development or product", but "concerned with the use of AI in creating content that ships with your game"; examples artwork, sound, narrative, localisation.
- If you used AI services in development or include them in the product, you must "describe that implementation in detail".
- **Pre-Generated** (created with AI tools during development, then shipped): game must not contain illegal or infringing content (Steam Distribution Agreement promise). Valve evaluates the output "the same way we evaluate all non-AI content".
- **Live-Generated** (created while the game runs): same as pre-generated plus you must state "what kind of guardrails you're putting on your AI" to stop illegal content. No example guardrails given on the page.
- Live-generated adult-only sexual content is not accepted "at this time".
- If a live AI service charges per input/output, access and payment must go through a Steam-supported method (price in base, microtransactions, subscription, or one-off DLC).
- "Efficiency gains through the use of these tools is not the focus of this section."
- Content rules apply "regardless of whether it is disclosed"; Valve compares survey answers with the build and the store page; some answers cannot be edited after approval without Steam Support.
### 3.2 History and press context
- Introduced 2024-01-10 (policy change allowing most AI games, with disclosure); disclosures show on the store page; an overlay report button exists for live-generated content; a later form revision narrowed the focus to player-consumed content, not behind-the-scenes tools [2][10][11]. The press items are secondary sources; the Valve page [1] is authoritative.
### 3.3 How our game falls out (interpretation, not Valve text)
| Item | Class | Disclose? |
|---|---|---|
| Midjourney concept layers (`art/concepts/**`, 15 of 16 jobs for the first chassis; PROVENANCE.md, PROMPTS.md) | pre-generated AI, concept references; the mech 3D model (`art/models/`) is Blender-built from them (D-023 pipeline) | yes, plainly: tool, how used, what a human changed |
| Final sprites/models/shaders/audio made by humans or code | not AI | state human-made |
| GIS data (OSM, etc.; M-005) | data-derived | not AI; licence bundle (M-125) |
| Kaiju driven by trained RL policies (D-005) | live AI **behaviour**: no text, image, audio or code is generated at runtime; policy picks inputs within the same rules as scripted units | state in description; **tick live-generated = No** (Q-NEW-120a); guardrails sentence provided anyway |
| Anything that calls an external AI service at runtime | none | not present; flag stays off |
- Rationale: Valve defines live-generated by "created while the game runs" content; an RL policy outputs control signals. Risk if Valve's reviewer reads it otherwise: they ask; we answer with the guardrail text (§3.4). Stage-gate: we never ship runtime text/image/audio generation without re-reading [1].
### 3.4 Draft guardrail text for the disclosure (for T-145)
"Kaiju behaviour is produced by neural-network policies trained offline in self-play and fixed at ship time. They output movement and attack commands only, chosen from a fixed action set; they cannot produce text, images, sound or code, cannot be prompted by players, and run entirely on the player's machine. They are bounded by the same physics and damage rules as every other unit. No runtime AI service is called."
### 3.5 What reviewers check (from [1])
Match between survey, build and store page; illegal/infringing content (relevant to D-009: IP denylist scan M-126 must be clean); player-visible description. Keep the inventory (M-120) so the description can be exact.

## 4. Demo rules [4][6]
- A demo has its **own App ID**, created from the base app landing page ("All associated packages, DLC, demos and tools" then "Add Demo"); application type Demo, base App ID entered in General Application Settings; own depots, builds, release checklist; upload with the demo's App ID.
- Store presence: either show on the base page, or a separate demo page which must describe only demo content, include a trailer and **at least 5 demo-specific screenshots**, mark capsules/library assets as demo; the Content Survey must match the demo (so the AI disclosure is repeated for the demo app).
- Release: "Release Demo..." or "upcoming" phase; if demo precedes the game, the base store page must be visible as coming soon; republish base page so Download Demo shows.
- Wishlist notification to full-game wishlisters: once, within two weeks of first playable demo release; 14-day cooldown per App ID.
- Demo and full-game players cannot matchmake together (design consequence: demo co-op is demo-to-demo only). Achievements not recommended. Shared depots need the full game released first; gate full-game content with `ISteamApps::BIsSubscribedApp`.
- Separate demo page gets user reviews; no own community hub.
### Next Fest [6]
- One Next Fest per title, ever. Developer account in good standing; base store page public; **publicly playable demo available when the fest begins**; game unreleased through the edition. Prologues/short versions of released games do not qualify.
- Demo build+assets review: submit ≥3 weeks before fest if the demo releases before the fest starts; ≥5 weeks if it releases before Press Preview. Updates after approval are not re-reviewed.
- Registration is from the base game's landing page. Fests run Feb, June, Oct; nav lists February 2027 and June 2027 editions (dates on those pages; verify).
- Timeline consequence: Steam Direct review/waiting periods (§7) plus a public coming-soon page (≥2 weeks) must precede; earliest realistic fest depends on the founders creating the app; track as a founder row.

| Asset | Size | Notes |

| Library capsule | 600x900 | must show logo, no other text |
| Library hero | 3840x1240 .png | artwork only, no words |
| Library logo | 1280 px wide and/or 720 px tall .png, transparent | logotype only |
| Library header | 920x430 | |
| App icon | 184x184 .jpg | community/client |
| Shortcut icon | 256x256 .ico/.png | |
| Bundle header | 707x232 | only if a bundle |
- Page [3] states that old dimensions are no longer accepted and larger sizes are accepted for most capsules: use the current templates.
- Capsule rules: title only (no quotes, taglines, review scores, awards, sale text, calls to act, other products); name legible; PG-13 suitable [12]. Timed text only via Artwork Override (≤14 days).
- Screenshot rules: gameplay only, no concept art, pre-rendered stills, award graphics or marketing text; menus only if unique; mark ≥4 screenshots "suitable for all ages" if content qualifies (our kaiju violence: probably not; decide when the survey is seen) [3].
- **Pixel-art consequence:** capsule sizes are not integer multiples of one internal resolution. Rule: compose capsule art in an integer-scaled oversize canvas (nearest-neighbour, one integer per asset), then **crop** to the target; the logo is vector/hand-pixelled at the target size. Cropping is not resampling. Screenshots: 1920x1080 = integer scale of the internal frame (Q-234).
### Trailer [5][13]
- Up to 1920x1080, 30/29.97 or 60/59.94 fps, ≥5,000 kbps (Valve's own example 20 Mbps), mov/wmv/mp4, H.264 preferred, AAC 44.1/48 kHz, stereo downmix, 16:9 preferred (4:3 accepted). No max length or count; the first two trailers precede screenshots.
- Steam transcodes the upload; poster 600x380 and thumbnail 232x130 auto, custom poster 1920x1080 png/jpg. Microtrailer is auto-generated, 6 s loop from the first trailer, not customisable. Recommendation: first trailer mostly gameplay with HUD, hook in under 10 s, works muted.

## 6. SteamPipe and tooling usable without an account [7]
- **Needs an account:** upload (steamcmd `+login` with a build account holding Edit App Metadata and Publish App Changes permissions; setting live on a released app needs a phone/mobile app on the account), real depot IDs, SetLive. Not possible for us.
- **Can be prepared now:** `scripts/app_build_<APPID>.vdf`, `depot_build_<DEPOTID>.vdf`, ContentBuilder folder layout (`builder`, `content`, `output`, `scripts`), exclusion lists, a wrapper script, with placeholder IDs and a `Preview "1"` default.
- `app_build` fields: `AppID`, `Desc` (internal), `ContentRoot`, `BuildOutput`, optional `Preview "1"` (logs and manifest only, nothing uploaded), `Local "<dir>"` (local content server), `SetLive "<branch>"` (not the default branch), `Depots { "<id>" "depot_build_<id>.vdf" }`.
- `depot_build` fields: `DepotID`, optional `ContentRoot`, `FileMapping { LocalPath "*" DepotPath "." recursive "1" }`, `FileExclusion "*.pdb"` (wildcards; also `"bin\tools*"`).
- Template (placeholders only):
```
"AppBuild" { "AppID" "0000000" "Desc" "kaiju demo <git sha>" "BuildOutput" "../output/" "ContentRoot" "../content/" "Preview" "1"
  "Depots" { "0000001" "depot_build_0000001.vdf" } }
"DepotBuildConfig" { "DepotID" "0000001" "FileMapping" { "LocalPath" "*" "DepotPath" "." "recursive" "1" }
  "FileExclusion" "*_BurstDebugInformation_DoNotShip*" "FileExclusion" "*.pdb" }
```
- steamcmd: `steamcmd +login <build_account> +run_app_build ../scripts/app_build_<APPID>.vdf +quit`; CI: log in interactively once and keep `config.vdf` so later runs use `+login <user>` only [7]. steamcmd itself is a separate Valve download that we do not fetch (open question Q-NEW-120b: its licence terms were not read).
- Unity side: demo and base game get separate depots (and a Mac and Windows depot each, with OS set on the depot). Exclude Burst debug and `*_DoNotShip` folders. Unity build is ours (T-140).
- Local dry run possible without account: `Preview "1"` still needs steamcmd; so only syntax can be self-checked (a small Python VDF parser test; no network).

## 7. Steamworks SDK and app fee: what waits for a founder
- Valve's SDK Access Agreement: if a Steam account is not tied to a Steamworks partner, you must accept the agreement to reach the SDK and documentation; downloading or using it counts as acceptance [8]. The SDK is required only to upload content; other features optional [9]. Hence **no SDK download by us** (consistent with M3 §safety limits); T-141's `IPlatformServices` seam stays null until then.
- Steam Direct [14]: **$100 per product**, non-refundable (recoupable after $1,000 adjusted gross revenue); identity verification, bank and tax paperwork (15-30 days); **21-day wait** between paying and release (first few titles); a public coming-soon page for at least two weeks; pre-release review 1-5 days. Per-app fee: base game and the demo (demo apps are created from the base app; demo fee not stated on [4] (verify)).
- Distribution Agreement, NDA and tax interview are signed in onboarding: founder acts.
- Founder checklist (tracked rows in M3): create partner account; pay fee; create base app and demo app; accept SDK agreement and drop the SDK in; fill survey (use T-145 draft); upload store art; set up build account; run `steamcmd` with the T-143 scripts; release.

## 8. Metric drafts
### M-120@v1 · Provenance coverage of shipped assets
- Definition: shipped assets with a valid provenance record / shipped assets. Shipped set = files under `Assets/` (non-package, non-generated), `art/` items referenced by the build manifest, audio, fonts, plus data layers. Record = tool, prompt sheet ref (if AI), human edits, D-023 stage, class in {pre-generated AI, human-made, data-derived, code-generated, third-party licensed} and a licence reference.
- Procedure: `Tools/Provenance` scans the build manifest file list (T-140) and `Assets/`, joins with `PROVENANCE.md`/sidecar records; unknown class = unknown.
- Threshold: **100 %**; any unknown blocks the build (no tolerance, per M3 plan). Also report a count by class for the disclosure.
- Source: Valve [1] (survey must match the build); our D-023.
### M-122@v1 · Store asset spec compliance
- Definition: every required asset present, correct exact pixel size, format, and rule check (no extra text on capsules is checked by review, not by script).
- Procedure: `Pipelines/capture` spec table (§5) verified by image header read: sizes exact for capsules/library; screenshots ≥1920x1080, ratio 16:9 exactly, count ≥5 (draft target 8-10); trailer ffprobe: codec h264, ≤1920x1080, fps in {30,29.97,60,59.94}, bitrate ≥5,000 kbps, mp4, AAC 44.1 or 48 kHz, 16:9; demo variant: ≥5 demo screenshots and a trailer.
- Threshold: 100 % of table rows pass; table version-stamped with the access date because Valve changes sizes [3].
### M-126@v1 · IP denylist scan
- Definition: hits of franchise/studio/character/design terms in shipped text, asset and file names, scene/prefab names, prompt sheets (`PROMPTS.md`), provenance and store text, and in image-prompt strings.
- Procedure: case-insensitive, word-boundary and normalised (strip spaces/hyphens, common leetspeak) match against `Tools/Provenance/denylist.txt` (maintained list; founders own additions; the list itself contains the terms so it is excluded from the scan and kept out of shipped files). Text only; image look-alike risk stays with the human review (Midjourney prompts already forbid named references, `PROMPTS.md` rule).
- Threshold: **0 hits**. Source: D-009; Valve infringing-content promise [1].
