Confidence: **A** = two or more sources agree within 1 %, at least one primary (agency, survey, standards body); **B** = one primary source or a small disagreement; **C** = conflict or secondary only (not emitted).

## 2. `landmarks` layer data (fits LayerApi 1 and `geo_export@v1`)

**Placement.** `IGeoLayer` order becomes terrain, water, buildings, **landmarks**, roads, faults. No interface change: parts that are prisms use the existing `GeoBuildingData` path with Core `BuildingId` source `landmark` (already present), so `BuildingsLayer`'s extruder (flat prisms; stepped parts as OSM Transamerica already does) is reused. Bridge cables and deck need `GeoMeshData`/collider output (T-023); T-022 covers prisms only.

**File** `landmarks.geojson` in each tile directory (GeoJSON, legacy `crs` = BayTM@v1, metres, float64; like `buildings.geojson`). A feature belongs to the tile of its representative point (R-004 §3.1). Linear features are cut at tile edges at shared float64 nodes.

| Field | Type, unit | Notes |
|---|---|---|
| `lid` | string | stable id, e.g. `lm:salesforce_tower:p3` |
| `bid` | string | Core id `landmark:<slug>[:part]` |
| `part_of` | string or null | owning OSM bid, so `RemoveBuilding` of the structure removes its roof parts (F-043). Null for bridge items |
| `kind` | enum | `crown`, `spire`, `clock_tower`, `bridge_tower`, `bridge_cable`, `bridge_deck` |
| `part_idx` | int | stack order (0 = lowest) |
| geometry | Polygon (prisms) or LineString (cable, deck axis) | BayTM x, z in m |
| `base_navd88_m`, `top_navd88_m` | float64 m, NAVD88 GEOID18 | `height_m` = top - base; `min_height_m` for floating parts |
| `roof_shape` | enum | `flat`, `pyramidal`, `spire` (apex only with `roof_height_m`, existing rule) |
| `y_navd88_m` | float64[] | cable/deck only, same length as coordinates |
| `width_m`, `diameter_m` | m | deck width, cable diameter |
| `height_source` | enum | `ctbuh`, `official`, `nrhp`, `lidar_3dep`, `osm_height` |
| `pos_source`, `source_ids` | string, string[] | indices into the manifest `sources[]` |
| `confidence` | `A` or `B` | `C` is never emitted (rule above) |
| `tol_height_m`, `tol_pos_m` | m | e.g. 3 for Ferry Building, 1 m datum for the GGB tower, 5 m position (R-004 §5) |

**Manifest.** An extra `layers[]` entry `{ "layer": "landmarks", "file": "landmarks.geojson", "sha256", "count", "sources": [...] }`; each source follows the existing rules (`licence`, `attribution`, `fetched_utc`, `source_sha256` = hash of the saved snapshot of the cited page or PDF). Licence values: `ODbL-1.0`, `US-Gov-PD` (3DEP, NOAA, HABS/HAER/NRHP) and one new id for cited facts from CTBUH/GGBHTD, e.g. `LicenseRef-facts-cited`.
**`geo_export@v1`.** Adds a `landmarks` array (as-built `lid`, `bid`, base, top, height, anchor, footprint). Additive.
**Contract-break check.** Adding the layer is non-breaking only if (1) a manifest without the layer stays valid (layer optional), (2) `GeoManifestValidator`/`GeoTileContext` do not refuse unknown layers or the new licence id, and (3) `m005_check.py` ignores unknown export keys. I did not read that code (brief); T-022 step 1 must test all three and bump to `geo_tile@v1.1`/`geo_export@v1.1` if any fails (Q-NEW-a). `LayerApi` stays 1.
**Size.** About 12 features of 1-2 kB each, so < 50 kB per district (*Assumed*).

Axis bearing of the bridge from the OSM tower centroids is 354.8 deg, hence the 264.8/84.8 perpendiculars. Eyes are my choice of geometry, not facts. A view gates only if its ray corridor lies in baked tiles; tiles missing from the corridor are sea-level plane in both renders; a view gates when >= 90 % of its skyline columns have their top row set by in-district features, else it is reported.

**M-005.4(d) default-height share at district scale.** Unit, exclusions, containment and fill chain as R-006 §2. Gate: **<= 2 % of footprint area over the union of the 15 tiles**, plus **<= 5 % (*Assumed*) per tile that has >= 10,000 m2 of qualifying footprint**; smaller tiles are reported (7 of the 14 new tiles are mostly water, §5). Count and perimeter shares reported. Risk: the lidar fill uses the 3DEP CA_SanFrancisco_B23 project (R-006); whether it covers the Marin side of GG is **not verified** (Q-NEW-e). Without lidar there, Marin footprints fall back to levels x 4.22 m or default.

**Multi-tile seam rule (M-005.10, new).** 19 internal tile edges: GG 3 x 3 has 12, SoMa 3 x 2 has 7. GG and SoMa are not adjacent (column i28 is between them).
- (a) Terrain: R-006 §1 excess jump E measured on the built surface along every internal edge, band + 5 m: p99 E <= 0.20 m, max E <= 0.50 m, as .9; plus no gap: edge vertices of both tiles equal to <= 1 mm in float64 BayTM (floating-origin shifts of multiples of 2048 m, MODULE.md). Known: r16 rows of neighbours differ by up to one quantisation step (about 2 mm at 125 m range), well under the limit.
- (b) Buildings: every `bid` is owned by exactly one tile; clipped pieces carry identical `height_m` and `base_navd88_m` (base from the full footprint, not the clipped piece); sum of piece areas = full footprint area within 0.1 %; no collider overlap > 0.05 m2 across an edge.
- (c) Landmarks: linear items continuous at shared nodes (<= 1 mm); a landmark's `lid` appears once; the GGB S tower is 48 m from the seam; HAER leg spacing decides whether both legs lie inside L0_26_37, and a test asserts it.
- (d) Load independence: a tile with absent neighbours builds without error and the same triangles for interior cells.
- (e) Traversal: GG to SoMa centre-to-centre is > 4096 m (M-015 floating origin); the seam checks run at both origins.

**M-060 landmark silhouette IoU (new).**
- *Definition.* For landmark L and view V in the §4 table where L has >= 400 px in the reference: IoU of the L mask in the game render against a reference mask, same camera as .7, after the +-1 px registration.
- *Game mask.* Object-ID render (`lid`/`bid` colour) of the built scene at its as-built float64 positions.
- *References.* **R-src**: the same `landmarks.geojson` plus buildings rasterised from source records (pipeline check). **R-ind**: 3DEP B23 first-return lidar DSM (R-006 §3 recipe) restricted to the landmark footprint + 5 m, with the landmark exempt from the thin-structure opening (R-006 §3 step 4). **R-doc** (bridge only): the HAER CA-31 elevation drawings projected at the same camera. Photos qualitative only.
- *Sub-pixel items.* Cables are 0.92 m wide (about 0.5 px at 2 km: 1 px = 1.28 mrad = 2.6 m). Both masks are dilated by 1 px before IoU for `bridge_cable`.
- *Thresholds.* vs R-src **IoU >= 0.97** for every (L, V) pair (0.98 in .7 is for whole-skyline columns; I allow 0.01 for 1-px edges of small masks). vs R-ind/R-doc **IoU >= max(0.85, IoU(F_v) - 0.02)** for confidence A landmarks; confidence B reported until the first founder checkpoint. All *Assumed, pending calibration*, derived from R-004 §6.7 (0.98/0.90) and the R-006 §3 noise-floor method.
- *Gate set.* Salesforce, Transamerica, GGB towers, GGB cables/deck (cables via R-doc only), Ferry Building (reported, tol 3 m).

## 5. Size check (R-004 §3.2)

- Per tile: `terrain.tif` 10-14 MB + `terrain.r16` 8.4 MB + `water.png` < 0.5 MB + buildings 0.1-2.5 MB + roads 0.1-1 MB + faults <= 0.05 MB = **about 19-26 MB**; R-004 plans on about 20 MB. Water tiles keep the full 2049^2 bathymetry (terrain files do not shrink), only buildings and roads do.
- 14 new tiles: **about 270-365 MB** cache (R-004's 20 MB average gives 280 MB). `landmarks.geojson` < 50 kB per district.
