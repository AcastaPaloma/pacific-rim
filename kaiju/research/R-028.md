## 1. Constraints taken from the read set
- Contract: `IKaijuBrain.Reset(seed, cfg)` / `Decide(in obs, ref intent)`, deterministic for a seed, no wall clock, no allocation, decide every `BrainPeriodSteps` (0.2 s), hold the intent between decisions (R-024 2.1-2.3).
- Information fairness (M-007 C4): the brain may target only entities visible or remembered <= 3 s; `TargetObs.Alive` is truth inside the memory window ("death is public", rev 3).
- The scripted baseline in `m007_3v4` (4 kaiju vs 3 shooting mechs): C1 FR_commit 0.494 (FAIL vs 0.60), C2 FE 0.923, C3 rate 0.075 /kaiju-min, thrash 0, C4 0 leaks; it loses more kaiju than `directcharge@1` (74 vs 45 deaths, 62 vs 189 mech kills per 100 runs) because flanking costs time under fire (rev 3). That trade-off is exactly what a learned policy should resolve.
- Stack: Python 3.12 + PyTorch (MPS available, no CUDA), gymnasium, stable-baselines3, ONNX/onnxruntime in the `kaiju` env; runtime "ONNX policies on Unity Inference Engine"; training "on a fast tactical environment that mirrors game parameters; validated in headless Unity" (STACK.md). Mac: Apple M5 Pro, 15 cores, 24 GB.

## 2. Observation space (D1)
Source fields are exactly those of `BrainObservation` (what the scripted brain perceives), plus the policy's own fed-back memory (current target, last maneuver, last switch time). Nothing from the harness truth reaches the actor. `Game.AI.Policy.ObservationEncoder`, layout version 1.

Frame: ego-centric, x forward along the self heading, y left; lengths / `SightRangeM` (1200 m), clamped to +-2. Angles as (sin, cos).
| Block | Size | Features (order is the contract, `PolicyLayout`) |
|---|---|---|
| Self | 25 | hp, speed/cruise, melee cooldown / 2 s, time since last target switch / `RetargetMinSeconds` (cap 1), live allies / 7, ally centroid (x, y), fraction of allies in Charge, usable targets / 8, current target one-hot (none + 8 slots), last maneuver one-hot (7) |
| Target slot x 8 | 15 | present, usable, visible, memory age / 3 s, x, y, distance, hp, sin/cos of the target's heading relative to its bearing to me, facing-me flag (45 deg), fraction of my live allies on it, is my current target, in melee reach, inside standoff |
| Ally slot x 7 | 24 | present, alive, x, y, distance, sin/cos relative heading, hp, state one-hot (6), its target as a one-hot over MY target slots (8), its target unknown to me, its target is mine |

- Fixed size for N mechs/allies: 8 / 7 slots (the contract maxima); empty slots are zero with `present = 0`, and the action mask hides them.
- Ordering invariance: slots are sorted by (usable/alive first, distance, EntityId as a tie-break only), so the vector does not depend on input order nor on id values (tests `Encode_IsInvariantToInputOrder`, `Encode_IsInvariantToEntityIdRelabel`). Ally targets are expressed in my slot indices, so focus coordination is visible without ids.
- Excluded on purpose: absolute position (the harness field is a 4 km box with walls, SF is not; prevents wall-exploiting policies), episode time (the game has no clock limit), entity ids, harness-only combat constants (mech DPS/range), any privileged state.
- Alternatives: (a) Deep Sets / attention over entity embeddings with a pointer head for the target [7] - permutation-equivariant by construction and size-independent, but ~3x the MACs (over the D8 bound unless slimmed) and harder to export; kept as the S2 ablation (same observation features per entity, so the encoder output can be reshaped). (b) Raw world frame - rejected, breaks rotation invariance and transfer. (c) Top-down raster - rejected, cost and loss of exact ranges.

## 3. Action space (D2)
`PolicyAction = (target in {none, slot 0..7}, maneuver in 7 primitives, speed tier in {0.6, 0.8, 1.0})`, decoded by `ActionDecoder` into `BrainIntent`:
| Maneuver | Intent written | State logged |
|---|---|---|
| Hold | speed 0, face the target (or keep heading) | Approach if a target, else Idle |
| Approach | head to target; speed 0 once inside standoff 250 m | Approach |
| FlankLeft / FlankRight | head to the waypoint on the standoff circle 60 deg further around the target (orbit step) | Flank |
| Charge | head to target at the tier; `Melee` when within reach 40 m (only Charge strikes) | Charge |
| Retreat | away from the nearest visible threat | Retreat |
| Regroup | toward the live-ally centroid; stop inside 150 m | Approach / Idle |

- Why high level: credit assignment over 1500 decisions per 300 s episode is tractable when one action means "flank this mech" rather than "turn 3 deg"; the tactics (whom to focus, when to flank vs charge, when to retreat, how to coordinate) are still fully learned - the decoder only does geometry, and no state machine, timeout or score weight is hand-tuned. Primitives are body-agnostic (heading/speed/target), which is the sim-to-target interface (section 5.4).
- Masking [8]: unusable targets (dead, forgotten) and target-needing maneuvers without a target are masked; the target head is sampled first and the maneuver mask is conditional on it. The decoder re-sanitises (unusable -> none, target-needing without target -> Hold), so C4 holds by construction even for a buggy network.
- Honest diagnostics: the reason code is derived from facts (voluntary vs forced switch), not chosen by the network, so C3 measures the policy. "Silent drop" (releasing a usable target to none and re-picking another) is blocked: none keeps the current target unless the maneuver is Retreat/Regroup, and a re-pick of a different target within 4 s of a drop is logged `RetargetVoluntary`.
- Alternatives: (a) continuous (heading, speed) + target - rejected for v1: the policy would have to learn low-level steering that the motor layer owns, longer horizons, and worse transfer; kept as a later ablation. (b) Flat discrete product (9 x 7 x 3 = 189) - equivalent but wastes the factorisation and makes masks awkward. (c) Options with learned durations - not needed at 5 Hz with a 10,000 t body.

## 4. Multi-agent setup (D3)
- Parameter sharing: one actor for all kaiju; agents differ only through their ego observation (no id, no role input; wing/centre roles must emerge). Shared parameters multiply the data per network by the pack size and generalise across pack sizes 1-8.
- CTDE: decentralised execution is mandatory (the runtime brain sees only its observation). The critic is training-only and may see privileged state: MAPPO [2] with a centralised critic over a global state (all kaiju and mech true positions/hp, including unseen mechs, mech DPS/range, time remaining). Plan: IPPO [3] (critic on the local observation) as the first baseline - the smoke uses it - then MAPPO in S2; keep whichever wins on the held-out pairs.
- Team reward with individual terms (section 6); agents that die keep their last transition open until the episode ends, so the team outcome reaches them too (no incentive to die early to avoid a wipe penalty).
- Asynchronous decisions: kaiju decide at staggered steps (phase = id mod period). A transition is completed by the same agent's next row (its events are the reward, its observation gives the bootstrap value); GAE runs per agent key (`kaiju_training.ppo.Rollout`).
- Alternatives: QMIX [4] (value factorisation, discrete) - strong on SMAC but off-policy replay with masked factored actions and variable team size is more fragile; MADDPG [5] - continuous-action oriented; separate networks per role - halves data, roles should emerge.

## 5. Training environment (D4)
### 5.1 Decision
Train on the existing engine-free C# 2D harness (`KaijuHarness`, `BrainLogWriter`), through a headless bridge process (`Tools/Training/bridge`, `KaijuBridge`), driven by Python over stdin/stdout. Reasons: (1) the harness is the M-007 reference; training and evaluation run the same code, so there is no port to drift; (2) the training encoder/decoder are the runtime `Game.AI.Policy` sources compiled unchanged, so the observation the policy learns on is byte-for-byte the one it gets in the game; (3) every episode writes `brain_log@v1` through the canonical writer, so M-007 primitives and C4 are measured on training logs with the T-033 tool; (4) throughput is sufficient (5.5).
Alternatives: Python port of the harness - faster to vectorise but doubles the source of truth (a 378-line harness plus 348-line brain), drift would silently invalidate C6; Unity ML-Agents in the 3D scene now - 100x slower per decision, no 3D kaiju body yet (T-005), and it couples training to the editor.

### 5.2 Protocol (version 1)
Hello (11 int32): magic `KJBR`, protocol, layout version, obs 313, mask 19, events 13, NT 8, NA 7, maneuvers 7, speeds 3, n_envs; Python takes the sizes from C#. Batch: `int32 n`, rows of `(env, agent, kind, episode, f32[13] events, f32[313] obs, u8[19] mask)`; kind 0 = decide, kind 2 = episode end for that agent. Reply: `int32 n` then n x (target, maneuver, speed); `-1` quits. Events per agent since its previous decision: damage dealt (/mech hp), damage taken (/kaiju hp), kills (mine), team kills, ally deaths, I died, win, wipe, timeout, voluntary switches, elapsed seconds, flanked commits, multi-kaiju commits.

### 5.3 Bridge mechanics
- One thread per env runs `KaijuHarness.Run()` with auto-reset; each policy kaiju's `IPolicyNetwork.Act` posts its observation and blocks. The coordinator waits until every env has posted, sends one batch (one decision per env, in env order, preceded by that env's end rows), and releases the envs with their actions. Batch k always holds each env's k-th decision, so thread timing cannot change a run (D10).
- Events come from the brain_log rows themselves: the harness writes into an `EventTap` TextWriter that parses `hit`, `death` and `decision` rows (and tees the log to disk for the first episodes, header `brain_id` rewritten to the policy id). Win = all mechs dead, wipe = all kaiju dead; training episodes stop early on either (evaluation keeps the full 300 s).
- Commit events for shaping follow R-024 3.1 online: a Charge entry toward T with no pack Charge toward T in the previous 8 s; flanked when >= 2 engaged members span >= 90 deg.
- Staging device (flagged): the harness constructs `new ScriptedKaijuBrain()` per kaiju and exposes no brain factory; editing the harness is outside T-041's write scope (the edit was refused). The bridge therefore compiles the unmodified harness sources with a bridge-local `Game.AI.ScriptedKaijuBrain` shim that delegates to a per-thread factory, with the real scripted brain referenced under an extern alias. Replace with a 3-line `HarnessScenario.BrainFactory` seam owned by the harness (open item O1).

### 5.4 Sim-to-target transfer (2D harness -> 3D body), staged
| Stage | What | Exit |

| T0 (now) | Tactics in the 2D kinematic harness (turn 0.5 rad/s, accel 2 m/s^2, cruise 9.12 m/s, melee 40 m) | C6 + C1-C4 pass in 2D |
| T1 | Domain randomisation [9] of the motor response and perception in the harness: turn rate x[0.5, 1.5], accel x[0.5, 1.5], cruise x[0.7, 1.3], reach 30-60 m, +0-0.4 s action latency, position noise sigma 0-10 m, sight 900-1500 m, FOV 240-300 deg | held-out pair-win does not drop > 0.05 vs T0 |

| T3 | Headless-Unity validation: the same `Game.AI.Policy` assembly behind `IKaijuBrain` in the 3D game, brain_log from the game; measure C1-C4 and C6 there | |C6(3D) - C6(2D)| <= 0.10 and C1-C4 pass in 3D |

## 6. Reward (D5)
### 6.1 Terms (per agent, from the event vector; weights in the run config `configs/*.yaml`)
| Term | Weight (*Assumed*, S1 start) | Kind |
|---|---|---|
| win (all mechs dead) | +5 | team, terminal |
| wipe (all kaiju dead) | -2 | team, terminal |
| timeout | -1 | team, terminal |
| team kill | +1 per mech | team |
| own kill (last hit) | +0.5 | individual |
| damage dealt | +1 per full mech hp | individual |
| damage taken | -0.5 per full kaiju hp | individual |
| own death | -1 | individual |
| ally death | -0.5 | team |
| voluntary switch | -0.05 | individual (C3 pressure) |
| time | -0.002 per s | individual |
| flanked commit (shaping) | +0.3, annealed to 0 by 60 % of the budget | team |
| unflanked multi-kaiju commit (shaping) | -0.1, annealed likewise | team |

### 6.2 Why this shape
The game wants kaiju that win in a way humans read as smart, not cheap (M-007). Outcome terms define winning; damage/kill/death terms densify it at the 5 Hz scale. The two M-007 primitives with a behaviour meaning (flanked vs unflanked commits) are offered as early shaping only, because rev 3 measured that flanking under fire costs the scripted pack time and kaiju: the policy must discover when flanking pays, not be paid to flank. Shaping is annealed away so the final optimum is the outcome optimum (potential-based shaping [6] would be policy-invariant; our commit bonus is not potential-based, hence the anneal).

### 6.3 Anti-gaming guards
1. C1-C4 are gates on logs, never final rewards (Goodhart): the policy is judged on the registered thresholds, which it cannot see.
2. C4 by construction: masked + sanitised targets; the actor never sees privileged state; the critic's privileged inputs are not exported.
3. C3: switch cost; reason codes from facts; no silent drop (3); thrash and switch rate monitored on every evaluation.
4. Flank farming: the commit bonus counts only fresh commits (8 s rule) and is annealed; an orbit-forever policy also pays the time cost and the timeout.
5. Wall camping: no absolute position in the observation; field size randomised in S3; evaluation reports the fraction of decisions within 100 m of the field edge (must stay <= 0.05, diagnostic).
6. Opponent exploits (e.g. baiting the mechs' nearest-target rule): mech rules are randomised in S3 (nearest / lowest-hp / random / focus targeting, flee on/off, kiting) and the S4 adversary league trains against exploiters.
7. Damage farming under respawn (churn scenario): kill reward decays per respawned mech; win is undefined under respawn, so churn is used for C3 only.
8. Reward hacking audit: every promotion runs the M-007 tool on 100 seeds and a 6-clip visual spot check (precursor of C5).

## 7. Curriculum (D6)
| Stage | Scenario | Purpose | Promote when (held-out seeds) |
|---|---|---|---|
| S0 | 1 kaiju vs 1 walking mech, no fire | approach / charge / melee | win rate >= 0.9 |
| S1 | `m007` (3 vs 2 decoys, no fire) | focus, flanking, assembly | pair-win vs scripted >= 0.5 and C1, C2 pass |
| S2 | `m007_3v4` (4 vs 3 shooting) - the gate scenario | trade-offs under fire, retreat | C6 gate (section 11) |
| S3 | randomised: kaiju 2-6, mechs 1-6, DPS 3-12, range 200-400 m, flee on/off, field 3-5 km, T1 motor randomisation; plus `m007_churn` (rev 3 addendum) | robustness, C3 under churn | no regression on S2 gate, pair-win >= 0.5 on the randomised set |
| S4 | adversarial mech league (section 8) | non-exploitability vs adaptive opponents | win vs league median >= 0.5, S2 gate still passes |
20 % of episodes replay earlier stages to prevent forgetting. Stages are scenario parameters of `HarnessScenario` (all public fields), so S0-S3 need no harness change; S4 needs a mech-control seam (O2).

## 8. Opponents: scripted vs self-play (D7)
- The kaiju's opponents in the game are human mech pilots; the harness mechs are scripted dummies. Pure scripted opponents risk a policy that exploits one rule; pure kaiju self-play is not the game (kaiju never fight kaiju).
- Decision: (1) S0-S3 against scripted mechs with randomised rules; (2) mixed packs: each kaiju is scripted with probability 0.25 in S3 (`scripted_ally_frac`), so the policy also cooperates with scripted allies (ad-hoc teamwork); (3) S4: an asymmetric league [10, 11]: a mech-side policy trained to beat the current kaiju policy, plus frozen past mech and kaiju snapshots and the scripted mechs; the kaiju trains against a mixture (50 % scripted / 30 % league / 20 % latest exploiter). This is where "self-play" happens - between the two sides, PSRO-style [12] - and it is the best proxy for humans available offline.

## 9. Runtime inference (D9)
- `PolicyKaijuBrain : IKaijuBrain` (engine-free, `Game.AI.Policy`) = encoder -> `IPolicyNetwork.Act` -> decoder, same cadence/phase as the scripted brain, 0 B per decision (*Measured*, `Brain_DeterministicForSeed_AndAllocationFree`).
- M1 evaluator: a C# MLP (tanh, float32) reading weights exported from PyTorch, implemented as an `IPolicyNetwork`; deterministic across platforms up to float rounding, testable in dotnet, no dispatch overhead. ONNX export of the actor stays the exchange artefact (STACK row kept), with a parity test ONNX Runtime vs C# evaluator (max abs logit error <= 1e-4). Unity Inference Engine becomes the evaluator only if a model outgrows D8 or measures faster under M-058.
- Runtime action selection: sampling from the masked distribution with a seeded RNG (unpredictable to players, reproducible for a seed); greedy argmax is the evaluation ablation. C6 and C1-C4 are measured in the shipped mode.
- Flag `kaiju.policyBrain` (constant `PolicyFlags.Policy`), default off; nothing installs the policy until a module and a trained artefact exist.

## 10. Model size bound (D8, M-058)
M-058: per-call p99 <= 50 us, per-frame p99 <= 0.33 ms, 0 B. *Measured* (`evidence/T-041/mlp_bench/`): a C# forward of the v1 actor 313-128-128-(9+7+3) tanh (58,880 MACs, 59,155 parameters) takes p50 10.5 us / p99 23.7 us with `System.Numerics.Vector<float>` and p50 13.6 / p99 30.1 us scalar on the M5 Pro (CoreCLR, Release), i.e. ~0.4-0.5 ns per MAC at p99. The 50 us per-call budget also carries the encoder and decoder and must survive IL2CPP on the Windows target, so the bound is **<= 100k MACs per decision** (~45 us p99 at the measured rate), with the evaluator required to pass the M-058 probe in EditMode and on the target PC. Growth beyond 100k (e.g. the v2 entity encoder) needs either a measured faster evaluator or a lower decision cost elsewhere; critics are unbounded (training only). Load: 3-4 kaiju at 5 Hz staggered is < 1 call per 60 fps frame, so the per-frame bound follows from the per-call bound.

## 11. Gate (D11)
The policy replaces the scripted brain as the default kaiju brain only when all hold:
1. **C6 win rate** (M-007@v1 C6 thresholds, unchanged): scenario `m007_3v4`, 200 seeds never used in training (training seeds start at 1,000+; evaluation seeds 1-200), each seed played by `scripted@1` and by the policy against the same mechs (duplicate format). Outcome order per run: (all mechs dead, mechs killed, total mech damage, kaiju alive, -time to win). A pair is won by the better outcome; pair-win rate over non-tied pairs >= 0.55 and Wilson 95 % lower bound > 0.50; more than 50 % ties = NOT_RUN. "Sides swapped" (R-024) is realised as a mirrored spawn per seed once the harness has a mirror knob (O3); until then the 200 seeds already randomise mech positions. The absolute win rate of each brain is reported beside it.
2. **C1-C4, no regression and no lowered threshold**: on the policy's own 100-seed logs in `m007` and `m007_3v4`, every clause passes at its registered threshold (C1 FR_commit >= 0.60 and >= 2 x the `directcharge@1` null; C2 FE >= 0.50, plus the addendum's FE vs `nofocus@1` if M-007 v2 adopts it; C3 thrash <= 0.10 and rate <= 3 /kaiju-min; C4 0 leaks). Note this is stricter than "not worse than scripted": the scripted brain itself fails C1 in `m007_3v4` (0.494) and the policy must still reach 0.60.
3. **M-058** with the policy brain: per-call p99 <= 50 us, 0 B.
4. **C5** (panel) runs on the policy when the game build exists, like for the scripted brain.
Tool work needed: the M-007 tool pools only `scripted@1` / `directcharge@1` / `nofocus@1`; it needs a candidate brain id and the C6 pairing (O4).

## 12. Compute budget on this Mac
Measured ~10k decisions/s end to end with 64 envs on CPU (5.5), i.e. ~36M decisions per hour. Plan per curriculum run: S0 5M, S1 30M, S2 150M, S3 200M, S4 300M decisions = ~685M = ~19 h at the measured rate (MAPPO's bigger critic may cost ~1.5x). Run 3 training seeds per configuration (RL variance) only for the final candidate; ablations use 1 seed on S1/S2. Learner on CPU by default (small MLPs are dispatch-bound on MPS); try MPS for the learner only at minibatch >= 4096 and keep it only if faster and determinism is not needed for that run. Wall cap: 24 h per full run; plugged in, keep-awake on.

## 13. Determinism and seeding (D10)
Harness seeded per episode (`base_seed + 100000 x env + episode`); scripted-ally choice seeded from the same seed; PyTorch CPU deterministic (`use_deterministic_algorithms`, fixed thread count), action sampling with a seeded `torch.Generator`; lockstep batching. *Measured*: two smoke runs give the same weights SHA-256 and byte-identical brain logs (`tests/test_bridge_e2e.py`). Runtime: `IKaijuBrain.Reset(seed)` seeds the action sampler; float transcendental functions may differ between Mono/IL2CPP and CoreCLR at the last bit, so cross-runtime replays compare intents within tolerance, not bytes (open item O5).
