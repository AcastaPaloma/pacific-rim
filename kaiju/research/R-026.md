# R-026: M1 metric registry, M-008 scenario, contracts, calibration plan (Track 6)

Requirement (prompt §4, verbatim): "Evaluators use only registered, versioned metrics plus their rubric. A new metric goes through steps 1-3 before it can fail anything."

Every threshold below is copied from its R-### draft; none re-derived. *Assumed* = unsourced in the draft.
Inputs read: plans/M1.md, R-020..R-025 metric sections, R-005 §8, Tools/Metrics/MODULE.md, M-002@v1.yaml. Web: one search (Unity docs) for the headless limit in §1.

## 2. M-006@v2 (proposal; no R-020..R-025 draft)
Keeps M-006.1-M-006.8 of R-005 §8 unchanged (thresholds, procedures, "passes when all pass in the same commit"). Adds, for buildings (plan Track 2: "impact energy and momentum clauses"). `kind: gating`, `headless: yes` (PlayMode `-batchmode`, physics only; no render), inputs `physics_log@v1` incl. `impact {bodies, J, ΔKE}` records (R-005 §8.9).
- **M-006.9 Delivered-energy identity.** Source R-021 §2.3. A locked 1e7 kg body hits a static-after-contact building stand-in of mass `M_b` in {5e4, 2.2e6, 3.6e7 kg} (R-021 house, mid-rise, tower M0 values, with `M_b = m_e = 0.75 M0`) at v_n in {2, 5} m/s, restitution e in {0, 0.5}. Compare logged `ΔKE` with `E_del = 1/2 mu v_n^2 (1 - e^2)`, `mu = m M_b/(m + M_b)`. Threshold: **|ΔKE - E_del| / E_del <= 3 %** *Assumed* (borrowed from the 3 % in M-006.3's e=0 ratio). `EnergyJ` of `BuildingDamaged` must equal that `ΔKE` exactly (float cast only): one source of truth, R-021 §2.3.
- **M-006.10 Momentum with light targets.** M-006.3 geometry repeated with the 1e6 kg box replaced by `M_b` of the three classes (mass ratio up to 1e7:5e4 = 200). Threshold as M-006.3: |Δp|/|p0| <= 0.5 %, |ΔL|/|L0| <= 2 % *A*, KE_after <= KE_before + 0.1 %, e=0 head-on ratio m1/(m1+m2) +- 3 %. Risk: large mass ratios are where PhysX depenetration (R-005 §4 R10) breaks conservation, so the numbers may need calibration (§4).
- **M-006.11 No energy gain through destruction.** Over every M-052 transition driven by an impact, `E_frac + E_ground + KE_ej <= dPE + W_ext`, taken from `physics_log` event pairs. Threshold 0 violations (R-021 M-052 rule, restated at physics level).
Version bump rule: v2 reports must still print v1 rows with identical values on the v1 scenes.

## 4. M-008 M1 scenario with stand-in bodies (T-038)
Requirement text (R-024 §5): "Host simulation budget met with 2 mechs + 3 kaiju + destruction". Q-019 (target PC) is open, so on the Mac only **relative** numbers are recorded and nothing absolute gates (M-058 is advisory on Mac, §1).
- **Bodies.** 2 placeholder mechs: `Units.Placeholder` rigid bodies at 80 m / 1e7 kg (R-005 §1, Q-106), scripted waypoint paths via the intent seat, no gait. 3 kaiju stand-ins: same mass class, driven by `scripted@1` through `IKaijuBrain` on the 2D kinematic harness at 9.12 m/s cruise (R-024 §1.3, *Assumed* speed), brain period 0.2 s staggered. 3 + 2 matches R-024's M-007 pack scenario.
- **Active destruction.** District `L0_30_36` (M0 tile, exists). Impactors: the 5 bodies walk a fixed 120 s route through a 1 km x 1 km block (*Assumed* size) so that >= 20 buildings reach state 3-4 (R-021 §2.3 sanity: 1e7 kg at 2-5 m/s is Complete for house and mid-rise). Debris capped at 64 pieces per building (R-021 §3), so at most 20 x 64 = 1,280 debris bodies. A scripted Mw 7.2 quake (R-022 §2) at t = 30 s adds shaking damage and 2.4 m peak offset to be exercised by M-053/054 in the same run (headless post-processing).
- **Run.** Fixed seed, step per C-2 (use Core's 0.02 s until resolved, because R-024 and R-023 assume it), 3 runs: A full scenario, B destruction off, C brain off. Logs: `brain_log@v1`, `physics_log@v1` (reduced: per-step totals only), optional `net_log@v1` in a loopback two-peer variant (T-031) kept out of this task.
- **Recorded (Mac).** Frame/step wall time p50/p99/max, managed allocation per step, debris body count, brain share (M-058 formula), steps over 16.7 ms. Gate on Mac (relative, *Assumed* 20 %): scenario A p99 <= 1.2 x the committed Mac baseline of A from the first accepted run; B and C used only to attribute cost. No claim about 60 fps on the target PC.
- **Harness not measurable on Mac:** Windows absolute budget, GPU cost, 4-peer net cost.

## 6. Founder calibration plan (W7, one sitting, about 10 captures per metric)
