# T-002 · Headless metric tools for M-001 to M-004 — reconciled expectation spec (v1)

Reconciled by the orchestrator from `expectations/T-002.A.md` (A, items n and §4.n) and `expectations/T-002.B.md` (B, items Cn and §4.n), 2026-11-14. The cited draft items carry the detail and are part of this spec. The metric specs are binding as written: `M-001@v1`, `M-002@v1` (`research/R-001.md`), `M-003@v1`, `M-004@v1` (`research/R-002.md`). Who depends on these tools (B): evaluators who pass or fail other agents' work every cycle, implementers who need "which contact slipped, which pixels are off-palette, where", and founders who calibrate from about 10 captures per metric.

## Acceptance criteria
**Correctness**
- **C1 Coverage.** Every sub-measure is implemented and reported by ID with value, threshold, margin, status and `gating`/`advisory`: M-001.1–.13; M-002.1–.5; M-003 a (output and internal, plus A₃/A₅ informational), b (DIG gate; O and DIG ≤ 0.5 advisory), c1, c2, d-i, d-ii, d-iii (advisory), d-iv, e (advisory), f; M-004 S0, S_px, C_px, F per motion class. A test compares the report's ID list with the spec's and fails on any extra or missing ID. (A1, BC1)
- **C2 Verdict rules equal the specs.** For each gating ID a fixture failing only that ID yields FAIL; one failing only an advisory ID still passes with a visible warning. (A2, BC5)
- **C3 Known answers.** Seeded synthetic fixtures built from closed-form truth, never by calling the tool's own functions, for every sub-measure; measured = truth within ≤ 1% relative (gait) or ≤ 0.005 absolute (shares). Includes at least one hand-computed, non-axis-aligned gait case (heading not along an axis, left-handed frame) so unit, sign and axis slips cannot hide. Test names carry the sub-measure ID. (A3, A §2, BC2)
- **C4 Boundaries and negative controls.** Each sub-measure has a boundary pair at 98% and 102% of its threshold and a negative control that fails **on that sub-measure only** where the fixture allows; the R-001 and R-002 control tables are reproduced (unquantised 0.847, bilinear upscale, inverted and no-haze scenes, posterised-no-dither and continuous ramp, screen-fixed dither under yaw, temporal-noise static). (A4, BC3)
- **C5 Colour maths.** CIEDE2000 matches the Sharma reference pairs to ≤ 1e-4; sRGB→Lab matches known D65 values. (A5)
- **C6 The worst case is never averaged away.** Verdicts use the worst capture and the worst contact; M-002.1 is the maximum over all contacts of all captures and names the worst five; one 0.12 m slip among 200 good contacts fails; unsmoothed peaks are printed beside smoothed ones. (A6)

**Honesty**
- **C7 Never passes by default.** Verdicts: `PASS`, `FAIL`, `INVALID_INPUT` (contract violation), `INCOMPLETE` (valid input but required evidence absent); exit codes 0 / 1 / 2 / 3, only PASS exits 0. Sub-measure statuses add `NOT_RUN`, `PENDING` and `NOT_APPLICABLE`. Vacuous cases are INCOMPLETE, never PASS (zero contacts, fewer than 3 steady strides, no evaluated dither frames, too few depth bands, a missing sequence or capture, fewer than 12 frames per profile, a missing sidecar, valid-pixel share below the registry minimum); malformed input (truncated file, NaN, wrong schema or units, bad bit depth, hash mismatch, gaps in `n`) is INVALID_INPUT. An emitter error is never reported as a metric failure. (A7, BC4, B §2)
- **C8 Panel items.** M-001.13 and M-003 f are read from a documented, validated ratings file (rater ID, rater type human/agent, blind flag, anchors, capture, score) and the spec's rules are applied (rater counts, anchors, exclusion, medians, floors). Without it those items are `PENDING` and the metric is INCOMPLETE; the report also carries a **`headless_verdict`** over all computable gating sub-measures, so a task loop can gate on the numbers while the panel is pending. The tool never invents or defaults a score. (A8, B §4.2)
- **C9 Gaming guards.** Header normalisers that differ from the registry's reference entry are flagged `NON_REFERENCE_NORMALISERS` (warn, not block: variant mechs and kaiju are legitimate); M-002.4 uses the spec's force hysteresis, not the emitter's flag; M-004 checks the camera motion measured from sidecar poses against the declared speed (> 10% apart is INVALID_INPUT) and rejects blank, frozen or fully masked sequences. (A14, B §4.14)

**Registry and versioning**
- **C10 Thresholds only in a versioned registry** (`Tools/Metrics/registry/`): each entry has sub-measure ID, value, unit, status (`derived` / `assumed_pending_calibration` / `calibrated`) and source. Moving any value across its boundary in a temporary registry flips the verdict with no code change; a source scan finds no threshold literal outside the registry and tests. A PASS resting on Assumed thresholds reads "PASS (provisional: n assumed)". (A9, BC8, B §4.16)
- **C11 Reports are complete and re-scorable.** JSON with metric ID and version, registry version and SHA-256, tool version, git commit, every input path and SHA-256, header-derived normalisers, every sub-measure, verdict, headless verdict, exit code, the coverage list (required / provided / missing), wall time; a human summary of at most 40 lines with failing IDs first. `rescore --registry <old>` reproduces an old report's verdicts; an old report is never silently reinterpreted under a newer registry. A second registry version coexists with v1 in a test; a metric marked `draft` cannot produce a failing verdict (orchestrator §4.4). (A10, BC7, BC9, BC10)

**Diagnostics**
- **C12 Failures point at the cause.** Gait: worst five contacts (contact ID, foot, step `n`, time, slip in m and % of foot length), the stride range of acceleration and yaw peaks, the capture name. Style: frame, sequence, pixel count and a diagnostic image (ΔE heat map with worst offender colours, dither mask, shimmer map, slip plot). On negative fixtures the injected fault's location appears in the top diagnostics. (BC6)

**Operation**
- **C13 Deterministic.** Two runs on the same inputs give byte-identical reports once the declared run block is stripped; fixtures regenerate bit-identically from a seed; independent of thread count and locale. (A11, BC11)
- **C14 Headless and fast.** No display, no Unity, kaiju env only. M-001/M-002 on the full eight captures < 60 s; M-003 on one capture set of ≥ 12 frames per profile < 60 s; M-004 on one profile-viewpoint set (six 180-frame sequences at 480×270) < 60 s and the full set < 10 min with deterministic parallelism. Timings recorded. (A12, A §4.17, BC11)
- **C15 Validators** for `gait_log@v1`, `style_capture@v1`, `palette_set@v1` run standalone, exit non-zero on error, and list **all** errors as file / line or key path / expected / found; they enforce the rules listed in A13 and BC12; a good example passes and at least 12 single-fault mutants each give the specific error; a 20-stride log validates in < 5 s. (A13, BC12)
- **C16 Calibration helper.** `calibrate` takes a ratings file and the reports for those captures and prints, per metric: rater agreement, anchor sanity, value-versus-rating table and plot, a proposed threshold per tunable sub-measure with the false-pass/false-fail counts, and a ready-to-review registry diff with a version bump. It never writes the registry, and refuses with fewer than 8 captures or misbehaving anchors. A synthetic-ratings test recovers a known cut. (BC13; serves orchestrator §4.3)
- **C17 Reference-panel baseline** in `evidence/T-002/baseline/`: the still-applicable measures on the 11 reference panels with R-002's masks and per-panel profiles; values reproduce R-002's tables within a stated tolerance; inapplicable measures are `NOT_APPLICABLE`, not pass; panels that fail stay failing and no threshold is touched. (A16, BC14)
- **C18 Usable by other agents.** One documented command per metric plus `validate`, `calibrate`, `rescore`, `list-metrics`; `--help` shows inputs and exit codes; bad input produces a clear message, not a stack trace; README and `MODULE.md` exist and every command in them is exercised by a test; `pytest` and the CLI run from a clean checkout. (A15, BC15)

## Readings of the research specs (implement these; list them in the README and report each as a spec defect for the scribe, never silently)
The implementer adopts the readings in A §4 and B §4 where the two drafts agree. Where they differ, or a rule is needed:
- **M-003 c2 sign** (A §4.10 signed; B §4.11 absolute): implement as written in R-002 (signed light-minus-dark, non-increasing with the + 0.5 allowance, 8 km ≤ 50% of 200 m) and also report B's absolute-value reading as an informational value.
- **M-001.12 and M-001.6 undefined terms** (A: gate the 3.1 s floor only; B: NOT_RUN): the registry holds the reference deceleration (0.30 g, from which R-001's 3.1 s follows as v/a), the rolling coefficient `c` and the power source (header `reactor_power_W`), all `assumed_pending_calibration`; the terms are computed from them and the log. The "≥ 2 mass variants when they exist" clause is `PENDING` and non-gating until variant logs are supplied.
- **Steps** are half strides; **stride period** is same-foot `contact_begin` to `contact_begin`, median over steady strides; **fore-aft / lateral** are projections on root heading.
- **Contacts** truncated by the log window are included and tagged, never dropped; the hysteresis starts in the off state.
- **`palette_sha256` canonical form:** SHA-256 of the UTF-8 bytes of the profile's colour list serialised as compact JSON (lowercase `#rrggbb` strings, declared order, no spaces). The renderer's capture tool (T-004) must use the same form.
- **M-004 class mapping** by nearest nominal speed within ± 10%, otherwise INVALID_INPUT; `pitch` and `dolly` sequences are validated and reported without a verdict; 180 frames in gating runs, 60 allowed in fixtures.
- **M-004 yaw versus translation** (B §4.1): R-002's own table suggests no single dither anchoring passes both. The tool implements the thresholds as written; the conflict belongs to the renderer task and the founders' calibration, not to the tool.

## What would disappoint the founders
The union of A §2 and B §2: a PASS built on nothing; means hiding the one bad foot-plant or the worst sequence; a black or frozen capture scoring perfect stability; thresholds in code or loosened to pass; trusting the emitter's header; numbers that change between runs; circular fixtures; reports without margins, hashes or versions; a tool that quietly "fixes" a research spec; a calibration helper that edits the registry or works from three captures; a baseline that looks like a pass on inputs the metric does not apply to.

## Evidence required (`evidence/T-002/`)
The union of A §3 and B §3: full `pytest -v` output with the coverage matrix (sub-measure → known test → negative test → fixtures); reports and summaries for every positive, negative and boundary fixture; validator runs on good and mutant inputs; the registry files, the registry-flip and rescore transcripts, the literal scan; the determinism diff; the timing table; one example of each diagnostic image beside the fault that caused it; the calibration helper run on synthetic ratings; a live exit-code table; the baseline reports and comparison table; the fixture generators and seeds; the list of spec readings and defects; `EVIDENCE.md` (criterion → artifact, command, commit).

## Questions for the founders (proposed; defaults in use)
- **Provisional passes:** does a PASS that rests on Assumed thresholds count at a gate before calibration? Default: it counts as provisional and is labelled so until the first calibration checkpoint.
- **Incomplete metrics at the M0 gate:** panel scores and the optional non-flat-terrain walk will be pending. Default: the gate uses the headless verdict plus the agent panel proxy, and the pending items are listed for the founders.
- **Calibration ratings:** default: both founders rate the same ~10 captures per metric plus anchors, independently; the helper uses the median and reports disagreement.
- **Version bump on calibration:** default: the spec stays `@v1`, each registry change creates revision `v1.N`, and reports name the revision they used.
