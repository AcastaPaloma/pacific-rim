# T-002 expectations, draft B (expect-B): headless metric tools for M-001 to M-004

Viewpoint: the evaluators who fail or pass other agents' work with these tools every cycle; the mech and renderer implementers who need "which contact slipped, which pixels are off-palette, where"; the founders who calibrate from ~10 captures per metric and must trust and re-run the numbers. Style references: none apply to the tools themselves; the baseline run (C14) uses `art/style_refs/` panels as stills.

## 1. Acceptance criteria (each testable; "test" = a named pytest or a stored report)
**Correctness**
- C1. Every sub-measure of `M-001@v1` (.1 to .13), `M-002@v1` (.1 to .5), `M-003@v1` (a, b, c1, c2, d-i to d-iv, e, f) and `M-004@v1` (S_px, C_px, F, S0) exists as an independently reported item with value, threshold, margin, pass/fail, and `gating` or `advisory`. Test: `test_inventory` compares the report keys to a list derived from the research specs; a missing sub-measure fails.
- C2. Known-answer fixtures: for each sub-measure a generated input with an analytically known value; the tool returns it within a stated tolerance (gait: Fr, stride period, duty factor, peak accel, yaw rate, start/stop time, slip; style: A_T, DIG, depth-band means, haze pairs, level/hue counts, block uniformity, S_px/C_px/F). Test names `test_known_<submeasure>`.
- C3. Negative controls: for each sub-measure an input that must FAIL it, failing for that sub-measure only where the fixture allows (e.g. Fr 0.45 run; 0.2 m slip on one contact; unquantised ramp; bilinear upscale; inverted haze; no haze; white-noise or screen-locked dither shimmer; temporal-noise static). Test `test_negative_<submeasure>`. The R-001/R-002 control tables are reproduced as pytest cases.
- C4. Never passes by default: missing file, wrong schema/version, empty or too-short capture (< 3 steady strides, 0 evaluated frames, < 2 depth bands, no contacts), NaN, gaps in `step.n`, or an unavailable required input yields verdict `ERROR` or `NOT_RUN` with a distinct exit code, never PASS. A metric whose sub-measures were partly not run cannot be PASS. Test `test_no_pass_by_default` over ≥ 10 malformed inputs.
- C5. Verdict logic equals the spec: M-001 PASS only if all 13 pass (panel score may be `PENDING`, which makes the overall verdict `INCOMPLETE`, not PASS); M-002 per its own list; M-003 per its gate list; M-004 per sequence class. Advisory items never flip a verdict but appear in the report.
**Diagnostics**
- C6. Every failing or marginal sub-measure names the cause location: gait gives worst 5 contacts (`contact_id`, foot, step `n`, time, slip in m and % of foot length), the stride or step range for accel/yaw peaks, and the capture name; style gives frame index, sequence, pixel count, and a diagnostic PNG (ΔE00 heat map with worst-offender hex values; dither mask; shimmer map; slip plot). Test: on negative fixtures the injected fault location (known contact, known pixel box) appears in the top diagnostics.
- C7. Human summary (≤ 30 lines) plus JSON; exit code 0 only for PASS; stdout summary line states metric ID@version, registry version, verdict, count of failing sub-measures.
**Registry and versioning**
- C8. Thresholds, band edges, tolerances and `Assumed` flags live only in `Tools/Metrics/registry/` files, each carrying `metric`, `version`, `status` (`seed`|`calibrated`), `date`, `source`. A grep test finds no numeric threshold literal in the code paths. Test `test_registry_override`: changing one value in a temp registry flips the verdict of a fixture with no code change.
- C9. Each report embeds metric ID and metric version, registry version and SHA-256, tool version, input-file SHA-256 list, git commit, seed, run timestamp, and the `Assumed`/`seed` status of every threshold used. `rescore --registry <old>` reproduces an old report's verdicts byte-for-byte (except timestamp); an old report is never reinterpreted under a newer registry. Test `test_old_report_reproducible`.
- C10. Adding a metric version is documented by a worked example in README and demonstrated by a test registry `v2` that coexists with `v1`; a metric not yet through research, tool and calibration is `status: draft` and cannot produce a failing verdict (orchestrator §4.4).
**Reproducibility and speed**
- C11. Two runs on the same inputs give identical JSON (timestamp aside) on the same machine; fixtures regenerate bit-identically from a seed. Each metric runs headless (no display, no Unity) in the `kaiju` env in < 60 s on a typical input (gait: 8 captures; style: 12 frames; M-004: 180-frame sequence at 480x270) and the report records wall time.
**Validators**
- C12. `validate gait_log|style_capture|palette_set <path>` runs standalone (no metric run), exits non-zero, and prints all errors (not just the first) as `file:line/field: what is wrong, expected, got`. Checks include units sanity (e.g. positions float64, quaternion norm, `yaw` range), step continuity, event-after-step ordering, header completeness, palette SHA matching `palette_sha256`, depth encoding bounds, and mask/file existence. Test: a good example passes; ≥ 12 single-fault mutants each give the specific error. Usable by emitters in < 5 s on a 20-stride log.
**Calibration**
- C13. `calibrate` takes a ratings file (capture id, rater id, 1-10 score, optional anchor flag) and the reports for those captures, and prints per metric: rater agreement, anchor sanity, the metric value vs rating scatter (PNG + table), the proposed threshold for each tunable sub-measure with the rating cut it came from and the false-pass/false-fail counts on the rated captures, and a ready-to-review registry diff with version bump `v1 -> v1.1` (it never writes the registry itself). It refuses (error) with < 8 captures, or when the negative anchors score ≥ 6. Test on synthetic ratings with a known cut recovering it.
**Baseline**
- C14. Reference-panel baseline: `evidence/T-002/baseline/` holds reports for the 11 panels covering the still-applicable measures (palette adherence at T=2/3/5 against their own profile, DIG, O, d-i, d-ii, d-iii, composition). Applicability is explicit: depth, c, d-iv and M-004 are `NOT_APPLICABLE`, not pass. The numbers match R-002's tables within a stated tolerance; panels that fail a gate (references are lossy) are reported as such, never excused by changing thresholds.
**Packaging**
- C15. README (every command, inputs, outputs, exit codes, how to add a version) and MODULE.md (module contract, owner, what it reads and never writes) exist; `pytest` and the CLI run from a clean checkout using only the `kaiju` env (any new package is in `environment.yml`).

## 2. What would disappoint them or mislead the loop
- A green report on garbage: empty log, zero gradient frames, a render of black. Silent PASS on skipped sub-measures is the worst outcome; it poisons every later evaluation.
- Only aggregate verdicts ("M-002 FAIL") with no contact, frame or pixel location; or a heat map that exists but marks the wrong place.
- Thresholds baked into code, or recalibration that rewrites history: old evidence becoming unreadable or silently re-verdicted.
- Fixtures that are so easy they prove nothing: positives only, or negatives that fail for two reasons at once so a broken measure still "fails correctly". The negative must fail on the sub-measure under test.
- Slow or flaky runs (random seeds, floating-point order, GPU use), so two evaluators get different numbers.
- Emitter errors reported as "metric fails": a gait log with a gap or float32 positions must be a schema error, not a slip failure that the mech implementer then "fixes" physically.
- Tool quietly "fixing" a research spec (e.g. using a threshold different from R-001) instead of implementing as written and raising a Q.
- Calibration helper that proposes thresholds from 3 captures, ignores rater disagreement, or edits the registry itself.
- Reference-panel baseline run on inputs the metric does not apply to, producing meaningless numbers that look like a pass or fail.

## 3. Evidence the implementer must produce (`evidence/T-002/`)
`pytest -v` output (with the test names above) and the coverage matrix `submeasure -> known test -> negative test`; reports for every positive and negative fixture; the 12-mutant validator run; `registry_override` and `old_report_reproducible` transcripts; two identical-run diffs; timing table per metric; one example of each diagnostic image next to the fault that caused it; the calibration helper run on synthetic ratings (input, output, diff); baseline reports for the 11 panels and a table comparing them to R-002's numbers; list of spec points where the implementation had to choose a reading (feeds section 4); `EVIDENCE.md` with the commit hash and exact commands.

## 4. Ambiguities and contradictions in the research specs (recommended reading in bold)
1. **M-004 translation vs yaw cannot both pass with one dither anchor per R-002's own table.** Yaw gates (S_px ≤ 0.01) are met only by direction-locked dither (0.0025); translation gates (≤ 0.12) are met only by world-anchored (0.095), while direction-locked scores 0.245 on translation and world-anchored 0.07 on yaw. Implement as written (tool is right to fail); **raise a Q for the renderer: hybrid anchor (direction for far/sky, surface for near) or a looser yaw threshold; do not change the tool**.
2. R-001 M-001.13 and R-002 (f) are panel scores, not computable from logs. **Tool ingests a ratings file; absent ratings = `PENDING`, overall `INCOMPLETE`**; (f) also needs ≥ 8 raters, anchors, exclusion rule (negative anchor ≥ 6) enforced by the tool.
3. M-001.12 needs `F_brake,max`, M-001.6 needs rolling coefficient `c` and `P`; the `gait_log@v1` header has `reactor_power_W` but no `F_brake,max` or `c`. **Registry holds `c` and `F_brake,max` per `unit_id` as provisional, with a Q to add them to the header in a `gait_log@v1.1`**; until then M-001.12 is reported as `NOT_RUN`-on-missing-input (so M-001 is INCOMPLETE), never defaulted.
4. M-001.12 "check across ≥ 2 mass variants when they exist": **PENDING until two variants exist; not a pass**.
5. "Steps" vs strides: M-001.10/.11 use steps (6.6 s = 2 steps at T_stride 6.6 s, so a step is half a stride). **Define step = half stride in README and the report.**
6. Slip "§5" definition (s_c from five sole points) is not in the part given to expectations; **slip = max over the five sole points of tangential displacement over the contact, in the contact-normal tangent plane, in metres**, with the per-point values in the diagnostic.
7. M-002.4 hysteresis needs an initial state. **Assume off at n=0; ignore the first F_on crossing mismatch window of 1 step**; report disagreement steps by index.
8. M-002 needs terrain slope and "when terrain exists": **missing = `NOT_RUN` listed in the report; verdict cannot be PASS-complete until run once terrain exists (M0 may accept INCOMPLETE for that single item, founder-visible)**.
9. M-003 gate list says "(d-i to d-iv)" while d-iii is "Advisory". **d-iii advisory; d-i, d-ii, d-iv gating** (matches the GAME_BREAKDOWN M-003 text).
10. M-003 (a): two thresholds (0.95 output, 0.995 internal); **both reported, the 0.95 output one gates, internal gates when `color_internal` is present** (renderer cannot hide a leak in the internal buffer).
11. M-003 c2: hazed ΔL* goes negative (4.3 -> -1.3) so "8 km ≤ 50% of 200 m" is trivially true for negatives. **Use |ΔL*|; also fail when the sign flips by more than the 0.5 noise allowance.**
12. M-003 sample sizes: "≥ 12 frames per profile" vs "≥ 12 captures" in (f). **Both: ≥ 12 frames per profile for metric (a)-(d); ≥ 12 rated captures for (f)**; fewer = `INCOMPLETE`.
13. M-003 (b): DIG threshold "≥ 80% of evaluated frames" with 0 evaluated frames (gradient share < 5% everywhere): **ERROR/NOT_RUN, not pass**; and O advisory until Q-NEW-a (references have O ≈ -0.3, so the ordered-dither reading conflicts with the references): the tool reports O but never gates on it.
14. M-004 S_px threshold is per px of motion with `k = ceil(1/speed)`; speed comes from the sidecar `motion.speed_internal_px_per_frame`. **Tool must also verify the logged speed against the pose change and refuse a sequence whose logged and measured speeds differ > 10%**. Sequence length is 180 frames in the protocol but 60 in the validation; **180 in gating, 60 allowed in fixtures**.
15. M-004 T3 flicker threshold (≤ 0.08) is much looser than T1/T2 (≤ 0.005): **keep as written, flag as a calibration item, since 0.069 is the best measured value, leaving little margin**.
16. M-003/M-004 thresholds are `Assumed`; **the tool prints `seed threshold` next to every such verdict** so founders see which results are provisional.

## 5. Open points for the founders (recommended default, marked Assumed)
- Q-a. Should an `INCOMPLETE` verdict (panel pending, terrain missing) block an M0 gate? **Default: yes for style/feel gates, with the two named items allowed pending in M0 only if the founders sign.**
- Q-b. Founder panel size for calibration ratings: **Default: both founders rate the same ~10 captures independently plus the 4 anchors; calibration helper uses the median and reports disagreement.**
- Q-c. Where baseline numbers on lossy references fail gates: **Default: report only, never tune a threshold to them.**
- Q-d. Whether to add `F_brake,max`, `c` and a `slip_ref_point` field to `gait_log@v1.1`: **Default: yes, before any mech emitter is written.**
- Q-e. Tolerance for known-answer fixtures: **Default: ≤ 1% relative for gait quantities, ≤ 0.002 absolute for style shares.**
