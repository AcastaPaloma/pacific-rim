# T-001 expectations, draft B (expect-B)
Task: Core (events bus, service registry, IDs, feature flags, clock, save contract). IDs: D-003, D-004, F-009, F-043, M-008; MODULARITY §1 rules 1–7, §3 L0.
Viewpoint: the ~20 modules that will sit on Core for two years, a host-authoritative Net layer added later (STACK), step-level replays for debugging, and world saves (F-043, D-020 permadeath) that must survive version changes.
Style references: none apply (no visual output). Test names below are suggestions; an equivalent named test is acceptable if `EVIDENCE.md` maps it to the criterion number.

## 1. Acceptance criteria

### Event bus
1. **Same-step delivery (F-009).** Every event published during step N, including events published from inside a handler, has reached every subscriber before step N+1 begins. Test `Bus_DeliversAllEventsWithinPublishingStep` asserts the step index seen by each handler equals the publishing step.
2. **Deterministic order.** For the same subscription sequence and publish sequence, the delivery trace (step, event type, subscriber, sequence number) is identical across 100 repeated runs, across `dotnet test` and Unity EditMode, and does not depend on hash codes, type names, GC timing or assembly load order. Test `Bus_DispatchTrace_IsReproducible` compares trace hashes. The ordering rule is written in `MODULE.md` in one or two sentences.
3. **Re-entrancy has defined semantics.** Publish, subscribe and unsubscribe from inside a handler never throw, never skip or double-deliver to an unrelated subscriber, and follow the documented rule (for example: a subscriber removed mid-dispatch receives nothing afterwards; one added mid-dispatch starts with the next event). Tests `Bus_UnsubscribeSelfDuringDispatch`, `Bus_UnsubscribeOtherDuringDispatch`, `Bus_SubscribeDuringDispatch`, `Bus_PublishFromHandler`.
4. **Runaway protection.** A handler cycle (A publishes B publishes A…) is stopped with an explicit error naming the event types, not a stack overflow or a frozen editor. Test `Bus_PublishCycle_FailsLoudly`.
5. **Fault isolation without silence.** A throwing handler does not stop the remaining subscribers for that event or later events; the exception is reported with event type and subscriber identity, and is countable. Under test, any handler exception is visible to the test (never swallowed). Test `Bus_ThrowingHandler_OthersStillReceive_ErrorReported`.
6. **Zero steady-state allocation (M-008).** After warm-up, 10,000 publishes allocate **0 bytes** on the managed heap, measured for 1, 8 and 64 subscribers, for a small and a ≥64-byte event struct, and with a handler that publishes a nested event. Measured in `dotnet test` (allocated-bytes counter) **and** in Unity EditMode (Mono GC allocation recorder). Test `Bus_Publish_AllocatesNothing_SteadyState`. Subscribe/unsubscribe may allocate; this is stated.
7. **Throughput baseline recorded.** Mean ns per publish-to-delivery at 1/8/64 subscribers, on the dev Mac, stored as a number in `evidence/T-001/` (no threshold yet; becomes the M-008 regression baseline).
8. **Events stay replicable and allocation-free by construction.** A test scans all event types visible to the bus and fails if any is a class or holds a managed reference field (strings, arrays, objects). Test `EventTypes_AreUnmanagedStructs`. This protects all future modules and the later Net layer, which needs events to carry IDs, never object references.

### Service registry
9. **Explicit failures.** Resolving a missing contract throws an error that names the contract type; registering a duplicate throws naming the contract and both implementations. Tests `Registry_ResolveMissing_NamesContract`, `Registry_DuplicateRegistration_Fails`.
10. **No state survives a test or a play session.** Running the whole Core suite twice in one process, and in random order, gives identical results; no static instance outlives its owner. Entering Play Mode twice with domain reload disabled (Unity "Enter Play Mode Options") boots cleanly both times with no duplicate-registration error. Tests `Registry_NoStaticLeak_AcrossFixtures`, PlayMode `Bootstrap_TwiceWithoutDomainReload`.
11. **Orderly teardown.** Disposable services are disposed exactly once when the registry is torn down, in reverse registration order (scene reload, return to hangar). Test `Registry_Teardown_DisposesReverseOrderOnce`.

### IDs
12. **Typed and safe by default.** Entity, building and player-slot IDs are distinct value types with no implicit conversion between them or from raw integers; `default` is an explicit invalid/none value that never equals a real ID. Reflection test `Ids_NoImplicitConversions`, test `Ids_DefaultIsInvalid`.
13. **Stable across processes.** An ID's serialised form and equality are identical across runs, machines, `dotnet` and Unity, and process restarts (no reliance on randomised string hashing or object identity). Test `Ids_SerialiseRoundTrip_AndCrossProcessStable` uses a committed fixture of serialised IDs.
14. **Building IDs do not depend on load order (F-043).** The same source building (e.g. its OSM key) yields the same `BuildingId` regardless of tile load order or which other buildings exist, so a re-import that adds buildings never moves damage onto the wrong building. Test `BuildingId_FromSourceKey_OrderIndependent`. ID space and collision test cover ≥ 10 million buildings (Bay-scale), with zero collisions in the test set: `BuildingId_NoCollisions_10M` (may be a slower, separately tagged test).
15. **Runtime entity IDs are never reused within a session.** After 1,000,000 allocate/release cycles no ID is issued twice, so a stale reference to a dead kaiju can never alias a new one (matters for later replication). Test `EntityId_NoReuseWithinSession`.
16. **Nothing assumes a count (D-004, D-003).** Player-slot tests run with 1, 2, 3 and 16 slots; Core source contains no player/mech/kaiju/pilot count constant and no `Player1/Player2`-style enum. Test `PlayerSlots_SupportN` plus a grep artifact.

### Feature flags (Rule 5)
17. **Unknown is off; missing is off; malformed is loud.** Unknown flag name reads off; a missing flags file reads everything off with one warning; a malformed file reports file and position and leaves everything off. Tests `Flags_Unknown_IsOff`, `Flags_MissingFile_AllOff`, `Flags_Malformed_ReportsAndAllOff`.
18. **The real file is the one tested.** A test loads the committed `Assets/Game/Config/FeatureFlags` in both `dotnet test` and Unity and checks every listed feature is off unless it is a shipped, accepted feature. Test `Flags_RepoFile_NewFeaturesDefaultOff`.
19. **Effective flag set is a snapshot.** The active set can be enumerated in a stable order and serialised, so it can be stamped into saves, replays and bug reports and later sent by the host to clients. Reads in the hot path allocate nothing. Test `Flags_Snapshot_StableAndSerialisable`.

### Clock
20. **Step index is the unit of time.** Engine-free code gets the fixed step in seconds (value from `Config/`, not a literal) and a 64-bit step counter; simulated time is derived from the counter, so after 10^7 steps (~55 h at 50 Hz, a long open-world session) it shows no accumulated drift. Test `Clock_NoDriftAfter10MSteps`.
21. **No hidden wall clock.** Core and Core.Contracts never read wall-clock time, `UnityEngine.Time` or unseeded randomness; tests drive the clock manually step by step. Grep artifact plus test `Clock_ManualStepping_DrivesBus`.
22. **Replay of a step.** A scripted test simulation using only Core (clock, bus, registry, IDs, flags) run twice from the same initial state, inputs and flag snapshot produces byte-identical event traces over 1,000 steps. Test `Core_StepReplay_Deterministic`.

### Save contract
23. **Round-trip.** 100,000 ID-keyed records (building-like: ID plus a small damage payload) round-trip with exact equality, including floats bit-for-bit. Write and read times and file size recorded as a baseline. Test `Save_RoundTrip_100k`.
24. **Versioned forever.** Every save carries a schema version and the writing build's version. A committed golden fixture `save_v1` must keep loading in every future build (the test is never deleted, only joined by `save_v2`…). A newer-than-supported file is refused with a clear message and is not modified. Tests `Save_GoldenV1_Loads`, `Save_NewerVersion_RefusedUntouched`, `Save_Migration_V1ToV2_Sample` (with a test-only v2).
25. **Never corrupt the last good save.** A failure in the middle of writing (simulated) leaves the previous save loadable and intact. Test `Save_InterruptedWrite_PreviousIntact`. Permadeath (D-020) and persistent destruction make this non-negotiable.
26. **Deterministic, locale-proof bytes.** Saving the same state twice gives byte-identical files, also when the process culture is `de-DE` or `tr-TR` (decimal comma, dotted-i). Test `Save_ByteIdentical_UnderForeignCulture`.
27. **Unknown data is not dropped.** Records of a type the current build does not know survive a load-save cycle unchanged. Test `Save_UnknownRecords_Preserved`.

### Structure and process
28. **Layering (Rules 1, 2, 7; §3 L0).** `Core.Contracts` and `Core` assemblies are engine-free (`noEngineReferences: true`) and reference only the .NET base library; only the adapter references UnityEngine; no Net or gameplay types in Core. Artifact: asmdef files plus a `dotnet build` of `DotnetTests/` with no Unity DLLs on the path.
29. **One test source, two runners, same list.** The sorted list of test names from the `dotnet test` TRX equals the list from the Unity EditMode XML (minus explicitly Unity-only tests, listed), all passing. Artifact: a diff of the two lists that is empty.
30. **Clean compile.** Unity compile log shows 0 errors and 0 warnings originating in Core assemblies.
31. **`MODULE.md` is usable by the next module's agent.** Filled from the §6 template, with contract versions, the ordering and re-entrancy rules, the exception policy, the allocation guarantee, how to add an event type and a service, and Q links. Includes a ≤20-line example of a module publishing and consuming an event.

## 2. What would disappoint the founders
- The footfall thud, camera shake or dust arrives one frame after the foot lands because the bus queued it to the next step (breaks F-009 and P1).
- A GC hitch at the moment two 10,000 t bodies collide, because events box or capture closures; or a "zero alloc" claim backed by one run with one subscriber.
- A flattened SoMa block reappears intact after an update, or damage lands on the wrong building after an OSM re-import, because building IDs were sequential.
- A save corrupted by a crash or a locale setting that permanently loses a mech, or a save quietly downgraded and stripped by an older build.
- `2` baked in anywhere (`Player1/Player2`, arrays of length 2), making D-004 a refactor later.
- Static singletons that force full domain reloads, slowing every agent's iteration, or leaking state between tests so results depend on order.
- A kaiju-AI handler that throws once and silently stops reacting for the rest of the session.
- A half-built feature switched on in a founder build because flags default on or a typo reads as on.
- String-keyed or reflection-based events where a typo fails silently at runtime.
- Over-engineering: a DI framework, ECS rewrite, networking hooks or gameplay event types inside Core; or a stub `MODULE.md` that the next twenty agents cannot learn from.
- Tests that pass in only one of the two runners.

## 3. Evidence the implementer must produce (`evidence/T-001/`)
- `dotnet-test.trx` and `unity-editmode.xml` (+ `unity-playmode.xml` for criterion 10), each with the exact command and commit hash in `EVIDENCE.md`.
- `test-name-diff.txt`: sorted test names from both runners and their diff (criterion 29).
- `alloc.txt`: per-scenario bytes allocated over 10,000 publishes, both runners, with warm-up count stated (6); `bench.txt`: ns/publish table (7).
- `trace-hashes.txt`: dispatch and replay trace hashes for every run (2, 22).
- `grep-counts.txt`: the grep commands and outputs for hard-coded counts, wall-clock and Unity references in Core (16, 21, 28).
- `save-baseline.txt` (write/read ms, file size for 100k records) and the committed golden fixture path (23, 24).
- `compile.log` excerpt with error and warning counts (30); asmdef listing (28).
- `EVIDENCE.md`: a table mapping each criterion number to its test name or artifact, command and commit. Evaluators should not need the implementer's narrative.

## 4. Open points for the founders (recommended default, marked Assumed)
- **Q-NEW-a Nested publish:** immediate (depth-first) or queued and drained within the same step? *Default: queued FIFO, drained before the step ends, with a per-step cap that fails loudly.*
- **Q-NEW-b Fixed step value:** *Default: 0.02 s (50 Hz) in `Config/`, Assumed until the physics research for stiff ArticulationBody PD drives says otherwise.*
- **Q-NEW-c Save compatibility promise:** how far back must saves load? *Default: every schema from v1 forever via migration; pre-M3 dev saves may be dropped only by founder decision.*
- **Q-NEW-d Save format at Bay scale:** JSON will be too slow for millions of buildings. *Default: JSON now, contract not tied to JSON, chunked or binary per tile in the World task, using the baseline from criterion 23.*
- **Q-NEW-e Runtime flag changes:** *Default: flags fixed at session start; host's snapshot authoritative in co-op; an editor-only live toggle later if needed.*
- **Q-NEW-f Threading:** *Default: the bus belongs to the single simulation thread; publishing from another thread is detected and reported in development builds.*
- **Q-NEW-g Handler exceptions in player builds:** *Default: log once per subscriber and event type, keep running, count them in a debug overlay; fail tests on any.*
