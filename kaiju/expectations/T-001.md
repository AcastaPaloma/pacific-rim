# T-001 · Core — reconciled expectation spec (v1)

Reconciled by the orchestrator from `expectations/T-001.A.md` (A) and `expectations/T-001.B.md` (B), 2026-11-14.
Each criterion cites the draft items it merges; where the drafts give more detail (test names, scenario sizes) that detail is part of this spec. Where they differed, the stricter outcome was taken unless noted. Test names are suggestions: `evidence/T-001/EVIDENCE.md` must map every criterion C# to its real test or artifact, command and commit.

## Acceptance criteria

**Structure**
- **C1 Layering.** `Core.Contracts` and `Core` are engine-free (`noEngineReferences: true`), reference only the .NET base library and no third-party package; exactly one adapter assembly references UnityEngine; no Net or gameplay types in Core. `dotnet build` of `DotnetTests/` succeeds with no Unity DLLs. (A1, B28)
- **C2 One test source, two runners.** The same test files run under `dotnet test` and Unity EditMode; the sorted test-name lists are equal apart from an explicit list of Unity-only tests; all pass; Core compiles with the C# version and API surface Unity 6000.6 supports. (A2, B29)
- **C3 Clean compile.** Unity compile log: 0 errors and 0 warnings originating in Core assemblies. (A3, B30)
- **C4 Extension proof.** A test-only sample module (outside Core) adds its own event type, service contract + implementation, feature flag and save record type and works end to end with zero edits to Core. (A4)
- **C5 `MODULE.md`.** Every field of the `MODULARITY.md` §6 template; contract versions; the ordering, re-entrancy and exception rules; the allocation guarantee; how to add an event and a service; a ≤ 20-line publish/consume example; Q links. (A5, B31)
- **C6 Repo hygiene.** `.gitignore` exception limited to `DotnetTests/` project files (`git check-ignore -v` shown for both cases); every new asset and folder under `Assets/` has its `.meta`. (A6)

**Event bus (F-009, M-008)**
- **C7 Same-step delivery.** Every event published in step N, including events published from inside a handler, reaches every subscriber before the outermost `Publish` returns, hence before step N+1; never deferred to a later step, frame or coroutine. (A7, B1; nested rule from A Q-a, stricter than B)
- **C8 Deterministic order.** The dispatch trace is identical across 100 repeats, across two separate processes, and across `dotnet` and Unity EditMode; independent of hash codes, type names, GC and load order; the rule is stated in `MODULE.md`. (A8, B2)
- **C9 Re-entrancy.** Publish, subscribe, unsubscribe-self and unsubscribe-other from inside a handler have documented, tested semantics: a subscriber removed mid-dispatch receives nothing afterwards; one added mid-dispatch starts with the next published event; nested events are queued FIFO and drained before the outermost `Publish` returns. (A9, B3)
- **C10 Runaway protection.** A publish cycle is stopped by a configurable cap with an explicit error naming the event types, not a stack overflow or a hang. (B4)
- **C11 Fault isolation without silence.** A throwing handler does not stop other subscribers or later events; the exception is reported through a Core error sink with event type and subscriber identity, is countable, and is visible to tests. (A10, B5)
- **C12 Zero steady-state allocation.** After warm-up, 10,000 publishes allocate 0 bytes for 1, 8 and 64 subscribers, for a small and a ≥ 64-byte event struct, and with a handler that publishes a nested event; measured under both `dotnet test` and Unity EditMode (Mono). Flag reads and clock reads also allocate 0 bytes. Subscribe/unsubscribe may allocate, and this is stated. (A11, B6)
- **C13 Typed events only.** No string topics; subscribing to one type never receives another; a test fails if any event type visible to the bus is a class or holds a managed reference. (A12, B8)
- **C14 Throughput baseline (informational, cannot fail).** ns per publish at 1/8/64 subscribers on the dev Mac, stored. (A13, B7)

**Service registry**
- **C15 Explicit failures.** Missing resolve and duplicate registration both throw, naming the contract type (and both implementations for a duplicate). (A14, B9)
- **C16 No hidden global state.** Two registries and two buses in one process are independent; the suite passes twice in one process and in random order; no mutable `static` fields in Core (grep artifact). Entering Play Mode twice with domain reload disabled boots cleanly both times; at most one static composition root, in the adapter only, reset on Play Mode entry and documented. (A15, A16, B10, A Q-f)
- **C17 Orderly teardown.** Disposable services are disposed exactly once, in reverse registration order. (B11)

**IDs (F-043, D-004, D-003)**
- **C18 Typed and safe.** Entity, building and player-slot IDs are distinct value types with no implicit conversions between them or from raw integers; `default` is an explicit invalid value; equality, hashing and ordering are value-based and allocation-free. (A17, B12)
- **C19 Stable across processes.** Serialised form and equality identical across runs, machines, `dotnet` and Unity; a committed fixture of golden values; lossless round-trip through string and save forms. No `Guid.NewGuid`, `string.GetHashCode`, `GetInstanceID` or spawn-order dependence. (A18, B13)
- **C20 Building IDs from the source key.** A `BuildingId` is (source namespace, 64-bit source id): independent of load order and of which other buildings exist; values above 2^32 round-trip; different sources (OSM way, OSM relation, hand-made landmark) cannot collide; zero collisions over ≥ 10 million IDs (may be a separately tagged slow test). (A19, B14, A Q-e)
- **C21 No stale aliasing.** Within a session a released entity ID never compares equal to any later-issued ID (1,000,000 allocate/release cycles). Reuse-with-generation and never-reuse both satisfy this. (A20, B15)
- **C22 No hard-coded counts.** Player-slot tests pass for N = 1, 2, 3, 16, 64; no player/mech/kaiju/pilot count constant, no `Player1/Player2`-style names, no type assuming one player maps to exactly one mech (grep artifact). (A21, B16)

**Feature flags (Rule 5)**
- **C23 Off by default, loudly.** Unknown flag reads off; a missing file reads everything off with one warning; a malformed file reports file and position and leaves everything off. (A22, B17)
- **C24 The committed file is the one tested.** A test loads `Assets/Game/Config/FeatureFlags` under both runners and checks every listed flag is off. A module adds a flag without editing Core code. (A23, B18)
- **C25 Session snapshot.** The effective flag set is fixed for a session, enumerable in a stable order and serialisable (for saves, replays, later host-to-client sync). (A23, B19)

**Clock**
- **C26 Step index is time.** Fixed step in seconds comes from config (Assumed 0.02 s until `research/R-005.md` recommends otherwise); a 64-bit step counter; simulated time derived from the counter shows no drift after 10^7 steps; the adapter makes Unity's fixed step equal to it and reports a mismatch. (A24, B20, B Q-b)
- **C27 No hidden wall clock.** Core never reads wall-clock time, `UnityEngine.Time` or unseeded randomness; tests step the clock manually. (B21)
- **C28 Step replay.** A Core-only scripted simulation run twice from the same state, inputs and flag snapshot yields byte-identical event traces over 1,000 steps. (B22)

**Save contract (F-043)**
- **C29 Round-trip.** 100,000 ID-keyed records round-trip exactly (floats bit-for-bit, large IDs included); write/read time and file size recorded as a baseline. (A26, A28, B23)
- **C30 Versioned.** Every save carries a schema version and the writing build's version; a committed golden `save_v1` fixture loads; a newer-than-supported file is refused with a clear message and left untouched; a sample v1→v2 migration with a test-only v2; an unknown version never loads silently wrong. (A25, B24)
- **C31 Crash-safe.** A simulated failure mid-write leaves the previous save loadable and intact. (A27, B25)
- **C32 Deterministic, locale-proof bytes.** Same state gives byte-identical files, also under `de-DE` and `tr-TR` cultures. (A26, B26)
- **C33 Unknown data preserved; modules own their sections.** Records of a type the build does not know survive a load-save cycle; Core knows nothing about buildings. (A28, B27)

## What would disappoint the founders
The union of A §2 and B §2. In short: a footfall effect arriving a step late; a GC hitch on impact; damage landing on the wrong building after a re-import; a lost mech from a corrupted or locale-broken save; a hidden `2`; static singletons and order-dependent tests; a silently dead handler; a flag that defaults on; string-keyed events; Core that reads like a framework (DI container, async queues, priorities, plugin loading, networking hooks, gameplay event types); a stub `MODULE.md`; tests that pass in only one runner.

Every item reproducible with one listed command.

## Decisions taken at reconciliation (Assumed; none blocks the task)
- Nested publish: queued FIFO, drained before the outermost `Publish` returns, with a loud cap. Both drafts recommended queueing; the earlier drain point was taken because F-009 needs exact-step coupling.
- Threading: the bus belongs to the simulation thread; a publish from another thread is detected and reported in development builds.
- Flags: fixed at session start; no runtime toggling in M0.
- Serialisation: no third-party dependency in Core; a minimal JSON reader/writer behind the save contract (binary or chunked formats can replace it in the World task).
- Player builds: a handler exception is logged once per subscriber and event type and counted; tests fail on any.
- Size guideline (soft): Core + Contracts under about 1,500 lines excluding tests.
