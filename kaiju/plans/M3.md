# M3 plan: Demo

Status: plan (2026-11-15, M2/M3 lead orchestrator, session 1). Only the groundwork tracks (1–3) start before M2 closes;
Track 4 (polish) and the demo build itself wait for M2. IDs from the block reserved in `ledger/IDS.md`: **T-140–T-159,
R-120–R-129, Q-230–Q-249, M-120–M-129**. Progress lives in `plans/M2_PROGRESS.md` (one file for both milestones until
M2 closes).

**M3 scope (orchestrator prompt §9):** "Polish, Steam build, AI-content disclosure, store captures." **Gate:** "Founders
sign off on a public demo." Under §15 the orchestrator makes every decision, but a sign-off is the founders' act, not a
decision: the gate stays open until they give it. Everything up to it proceeds.

**Safety limits that shape M3 (§15, not decisions):** no publishing, no store or partner accounts, no money, no
licence acceptance. So: no Steamworks partner app, no SteamPipe upload, no store page, and **no Steamworks SDK download**
(it requires accepting Valve's SDK licence). Everything is built to the point where a founder only has to create the app,
accept the SDK licence, drop the SDK in, and run one command. Each of these is a tracked row ("founder action"), not a cut.

**Requirement text served:** F-063 "Host-authoritative online co-op over Steam; N player slots" · D-009 "Commercial release
with **original IP**" · D-022 / P4 (every frame matches the style references; store captures are frames) · D-023 "Concept
art pipeline: Midjourney driven through computer use … then Blender, then Unity" (the source of the AI-content
disclosure) · D-005 "Kaiju are controlled by trained RL policies" (live AI behaviour, disclosed as such).

## Track 1 · Steam build pipeline scaffolding (all pillars; ships them)

- **Goal.** One command produces a reproducible player build (macOS now; Windows x64 when the build module is present,
  Q-231) with a build manifest, the Bay tile set copied from the cache bake (M2 Q-200), feature-flag snapshot, version
  stamp, licence/attribution bundle for every geo layer (ODbL, PDDL, US-Gov-PD), and a headless smoke test (boot →
  composition root → load one district → quit, exit code and log). SteamPipe `app_build`/`depot_build` VDF **templates**
  with placeholder IDs, and a `Platform` abstraction (`IPlatformServices`: identity, lobby, P2P transport adapter for
  `Net.ITransport`) with a **null/loopback implementation** so the Steam adapter is a drop-in later.
- **Modules.** `Tools/Build/` (C# editor build entry `Game.Tools.Build.PlayerBuild.Run`, shell driver `build.sh`,
  manifest writer), new `Platform.Contracts` + `Platform.Null` (L1/L2), `Pipelines/build/` (attribution bundle, tile copy).
  Flag `platform.steam` (default off; no implementation until the SDK row closes).
- **Gated on.** M-121 (build reproducibility: two builds from one commit have identical manifests and content hashes
  except the timestamp field; smoke test exit 0), M-125 (attribution completeness: every shipped data layer has its
  licence and attribution text, 100 %).
- **Tasks.** T-140 build entry + manifest + `build.sh` (3; one Unity run). T-141 Platform contracts + null impl + Net
  transport adapter seam (3, dotnet). T-142 attribution bundle + tile copy (2, Python). T-143 SteamPipe VDF templates +
  `README` of the founder actions (1). **≈ 9 steps.**

## Track 2 · AI-content disclosure (D-009, D-023)

- **Goal.** A truthful draft of the Steam AI-generated-content disclosure, backed by a machine-checked inventory: every
  shipped asset has a provenance record (tool, prompt sheet, human edits, D-023 pipeline stage) and is classed
  pre-generated AI / human-made / data-derived (GIS); live AI behaviour (RL kaiju policies, D-005) described with its
  guardrails (it produces behaviour, not content). IP check: no franchise names, designs or iconography (D-009).
- **Modules.** `Tools/Provenance/` (Python: scan `art/`, `Assets/` imported assets, provenance records; report),
  `docs/store/ai_disclosure_draft.md`.
- **Research.** R-120: Steam's current content survey and AI disclosure rules (pre-generated vs live-generated, what must
  be described, what reviewers check), demo rules (Steam Next Fest eligibility, demo app requirements), store asset specs
  (capsules, screenshots, trailer), and SteamPipe/depot tooling usable without an account.
- **Gated on.** M-120 (provenance coverage 100 % of shipped assets; unknown provenance blocks the build), M-126 (IP
  denylist scan: zero hits for franchise terms in shipped text, asset names and prompt sheets).
- **Tasks.** T-144 provenance scanner + M-120/M-126 (3). T-145 disclosure draft from R-120 + the inventory (1).
  **≈ 4 steps + 1 research.**

## Track 3 · Store capture tooling (P4, P3, P1)

- **Goal.** Deterministic, headless captures for screenshots and trailer footage: scripted camera paths over real Bay
  viewpoints (M-005 viewpoints reused), integer-scaled pixel output at the store resolutions, lossless frame dumps,
  per-frame style metrics (M-003/M-004) so no store frame breaks the look, and an encode step that preserves pixels
  (nearest-neighbour scaling, chroma settings that keep dithering).
- **Modules.** `Tools/Capture/` (Unity runtime capture path driver, camera path asset `capture_path@v1`), `Pipelines/capture/`
  (Python: frame checks, contact sheets, encode). Reuses `Game.Tools.StyleCapture` where it fits (read its contract,
  extend by a new file).
- **Research.** R-121: capture and trailer practice for pixel-art games (integer scale, codec settings that keep dither,
  frame pacing, Steam screenshot/trailer specs from R-120), and a shot list per pillar.
- **Gated on.** M-122 (store asset spec compliance: sizes, formats, count), M-123 (every capture frame passes M-003@v1
  gated groups and M-004 for motion clips), M-124 (encode fidelity: decoded trailer frames vs source ΔE ≤ 2.0 on ≥ 99 %
  of pixels).
- **Tasks.** T-146 capture plan document (shot list, paths, specs) (1). T-147 `capture_path@v1` + Unity driver (3, Unity).
  T-148 frame checks + encode + sheets (3, Python). **≈ 7 steps + 1 research.**

## Track 4 · Polish and the demo build (waits for M2)

- **Goal.** A public-demo build: demo scope (Q-230), onboarding to intent controls, HUD for D-019 limits (power, heat,
  ammo, strain), settings (graphics, input remap, audio), audio pass (Audio module), crash-free soak, performance on the
  target PC, accessibility basics (colour-blind-safe UI within the palette, subtitles), and the founders' playtest.
- **Gated on.** M-127 (boot to gameplay ≤ R-122 target on the target PC), M-128 (2 h soak with 2 players, zero crashes,
  no leak above budget), M-008 absolute, every M1/M2 pillar metric still passing, founder sign-off.
- **Research.** R-122: demo scope and polish priorities from comparable demos (what a 30–60 min demo must show for each
  pillar), onboarding for intent control, HUD readability in the pixel style.
- **Tasks.** T-149–T-156 (staged; briefed when M2 closes). **≈ 20 steps + 1 research.**
